**Пользовательские сценарии «Альфа Защиты»**

**Статус:** планируемое поведение с гостевым режимом, 26 октября 2026 года. Сценарии описывают согласованные требования, а не уже реализованные функции. Анализ, HTTP-обработчики и формы описанных проверок пока не реализованы.

Основа: [заявка](kharchenko_application.md), [спецификация](SPECIFICATION.md). Объектные и классовые диаграммы: [kharchenko_diagrams.md](kharchenko_diagrams.md).

**Общие условия**

Все пять проверок доступны гостю и вошедшему пользователю. Гостевой результат доступен только на текущем экране: он не сохраняется в постоянной истории и может потеряться после закрытия или перезагрузки страницы. CSV, личная история и отзывы доступны только после входа. Гостевой перевод оценивается только по введённым сведениям; история транзакций ему недоступна.

Для каждой проверки можно добавить необязательный контекст свободным текстом; пользователь не должен сам размечать признаки мошенничества чекбоксами. Результат содержит оценку, выявленные признаки, объяснения, рекомендации и ограничения. Результат проверки, выполненной после входа, сохраняется в личной истории. Неизвестные сведения, отсутствие данных и ошибка обработки не означают отсутствие риска; результат не гарантирует безопасность.

**S01. Вход и просмотр своей истории с другого устройства — F01, F08**

**Участник:** пользователь сервиса.

**Условия:** открыт сайт; для проверки сохранности данных пользователь выполняет любую проверку из S02–S06 после входа.

**Ход:**

1. Пользователь регистрируется, если аккаунта ещё нет, затем входит в свой аккаунт.
2. Выполняет проверку и открывает её сохранённый результат.
3. Выходит из аккаунта.
4. Открывает сайт на другом устройстве и входит с теми же данными.
5. Открывает личную историю и ту же проверку.

**Результат:** доступен ранее сохранённый ответ без повторного анализа; пользователь видит только свои данные.

**Ошибки:** при неверных данных вход не выполняется; после выхода личные данные недоступны без входа; чужую проверку открыть нельзя. Если проверок ещё нет, история показывает пустое состояние.

**S02. Проверка текстового сообщения — F02**

**Участник:** гость или вошедший пользователь.

**Условия:** есть текст сообщения, которое требуется проверить.

**Ход:**

1. Пользователь открывает проверку сообщения.
2. Вводит обязательный текст; при необходимости дополняет его контекстом.
3. Отправляет сообщение на проверку.
4. Читает результат и рекомендации.

**Результат:** гость читает ответ на текущем экране без сохранения; для вошедшего пользователя анализ сообщения сохраняется в личной истории.

**Ошибки:** пустой текст не принимается; при ошибке обработки выводится понятное сообщение без вывода о безопасности. Если сведений недостаточно, результат сообщает об этом.

**S03. Проверка ссылки — F03**

**Участник:** гость или вошедший пользователь.

**Условия:** есть ссылка, безопасность которой вызывает сомнения.

**Ход:**

1. Пользователь открывает проверку ссылки и вводит обязательный URL.
2. При необходимости добавляет сопроводительное сообщение, ожидаемый сайт или организацию и общий контекст получения ссылки.
3. Отправляет ссылку на проверку.
4. Читает выявленные признаки и рекомендации.

**Результат:** гость читает ответ на текущем экране без сохранения; для вошедшего пользователя результат проверки URL сохраняется в личной истории.

**Ошибки:** пустой или некорректный URL не принимается. Отсутствие ожидаемого сайта допустимо; недостаточность сведений и техническая ошибка не выдаются за безопасный результат.

**S04. Проверка аудиозаписи — F04**

**Участник:** гость или вошедший пользователь.

**Условия:** есть аудиозапись разговора для проверки.

**Ход:**

1. Пользователь открывает проверку аудио и выбирает обязательный аудиофайл.
2. При необходимости поясняет, кто участвует в разговоре, и добавляет общий контекст.
3. Отправляет запись на проверку.
4. Читает результат анализа содержания разговора и рекомендации.

**Результат:** гость читает ответ на текущем экране без сохранения; для вошедшего пользователя результат проверки аудиозаписи сохраняется в личной истории.

**Ошибки:** файл отсутствует, не поддерживается или превышает установленный лимит — система объясняет причину отказа. Если речь не удаётся надёжно разобрать, система сообщает об ограничении; это не означает, что разговор безопасен.

**S05. Проверка скриншота переписки — F05**

**Участник:** гость или вошедший пользователь.

**Условия:** есть изображение переписки для проверки.

**Ход:**

1. Пользователь открывает проверку скриншота и выбирает обязательное изображение.
2. При необходимости поясняет, какие реплики принадлежат ему, и добавляет общий контекст.
3. Отправляет изображение на проверку.
4. Читает результат анализа переписки и рекомендации.

**Результат:** гость читает ответ на текущем экране без сохранения; для вошедшего пользователя результат проверки скриншота сохраняется в личной истории.

**Ошибки:** файл отсутствует, не поддерживается или превышает установленный лимит — система объясняет причину отказа. Нечитаемый текст и неясная принадлежность реплик отражаются как ограничения, а не как отсутствие риска.

**S06. Загрузка транзакций и оценка предполагаемого перевода — F06, F07**

**Участник:** гость или вошедший пользователь; импорт CSV доступен только после входа.

**Условия:** пользователь собирается перевести деньги; вошедший пользователь может предоставить историю транзакций, гость работает без неё.

**Ход:**

1. Гость сразу переходит к шагу 3. Если вошедший пользователь хочет предоставить историю, он скачивает шаблон, заполняет CSV и загружает его; иначе также переходит к шагу 3.
2. Система проверяет CSV и сохраняет корректную историю. Повторная загрузка заменяет прежнюю историю целиком; интерфейс заранее сообщает об этом.
3. Пользователь открывает проверку перевода и вводит обязательные сумму в рублях и назначение: покупка, возврат долга, подарок/помощь, свои счета, другое или неизвестно.
4. При необходимости указывает условный стабильный идентификатор получателя, текст просьбы о переводе и общий контекст. Вошедший пользователь также может выбрать получателя из своей загруженной истории.
5. Отправляет сведения на проверку. Для гостя система анализирует только введённые сведения; после входа дополнительно учитывает доступную историю пользователя, если она есть.
6. Пользователь читает результат, пояснения об использованных данных и рекомендации.

**Результат:** гость читает оценку на текущем экране без сохранения; для вошедшего пользователя она сохраняется в личной истории. Сервис не выполняет и не блокирует банковскую операцию.

**Ошибки:** гостю недоступны загрузка CSV и чтение транзакций. При некорректном CSV вошедший пользователь получает проблемную строку и причину, прежние данные сохраняются. Некорректная сумма и незаполненное назначение требуют исправления; вариант «неизвестно» допустим. Отсутствие истории или получателя ограничивает выводы, но не означает отсутствие риска.

**S07. Обратная связь о сохранённой проверке — F08, F09**

**Участник:** вошедший пользователь, которому принадлежит проверка.

**Условия:** пользователь вошёл в аккаунт; в его личной истории есть сохранённый результат. Для гостевого результата отзыв недоступен.

**Ход:**

1. Пользователь открывает свою проверку из истории.
2. Указывает последующий исход: мошенничество, обычная ситуация или неизвестно.
3. При желании добавляет комментарий.
4. Отдельно может разрешить использование данных этой проверки для подготовки будущего обучения. Разрешение необязательно и по умолчанию выключено; отзыв можно отправить без него.
5. Сохраняет отзыв, а позже при необходимости исправляет исход или комментарий.

**Результат:** отзыв сохранён отдельно от исходного прогноза и помечен как непроверенное сообщение пользователя. Разрешение на будущее обучение учитывается отдельно от факта отправки отзыва и относится только к этой проверке. Прогноз не перезаписывается; сбор отзывов не запускает дообучение и сам по себе не улучшает качество модели. Наличие разрешения не означает, что данные уже проверены или использованы для обучения; само обучение не входит в сценарий.

**Ошибки:** без входа, к гостевой или чужой проверке оставить или изменить отзыв нельзя; исход должен быть выбран. При сбое сохранения система сообщает, что отзыв не сохранён, и сохраняет прежнюю версию, если она была.
