**Подготовка к записи**

- Адрес сайта указан в [итоговой заявке](kharchenko_final_application.md). Для демонстрации нужен новый аккаунт с пустой историей; пароль выбрать самостоятельно.
- Подготовить [обычный QR](examples/demo/qr-ordinary.png), [подозрительный QR](examples/demo/qr-warning.png), [скриншот переписки](examples/demo/warning.png) и `demo_history.csv` из конца этого документа. Все примеры вымышленные.
- Сценарии расположены в порядке записи. Перед каждым блоком произнести его название. Вступление — кратко о задаче сервиса; весь ролик — до 8–9 минут.

### [ Сценарий 1 - Регистрация и вход в аккаунт ]

1. Пользователь открывает главную страницу и выбирает «Регистрация».
2. Вводит свободный логин, пароль и повтор пароля.
3. Если логин занят, пароль слишком простой или пароли не совпадают, система показывает ошибку и предлагает исправить данные.
4. При корректном вводе система создает аккаунт и открывает страницу входа.
5. Пользователь вводит свой логин и пароль.
6. Система открывает страницу аккаунта и показывает логин вошедшего пользователя.
7. Пользователь открывает «История проверок». Для нового аккаунта система показывает пустую историю.

### [ Сценарий 2 - Проверка сообщения без регистрации ]

1. Пользователь открывает сайт в отдельном приватном окне браузера, не входя в аккаунт, и выбирает «Текст».
2. Вводит сообщение: «Срочно переведите деньги на безопасный счет. Никому не говорите. Назовите код из СМС».
3. Нажимает «Проверить».
4. Система показывает результат с предупреждением, обнаруженными признаками и рекомендациями. Пользователь показывает конкретное основание и связанный с ним фрагмент сообщения.
5. Для сравнения пользователь проверяет текст: «Привет! Завтра идем в библиотеку после уроков?».
6. Пользователь показывает результат. При отсутствии предупреждения система напоминает, что отсутствие найденных признаков не гарантирует безопасность.
7. Гостевой результат не сохраняется в личной истории. Пользователь закрывает приватное окно и возвращается в основное окно с открытым аккаунтом.

### [ Сценарий 3 - Проверка ссылки и ожидаемой организации ]

1. В основном окне пользователь выбирает «Ссылка».
2. Вводит `https://sberbank-login-security-check.example/verify`, в поле ожидаемой организации — «Сбербанк».
3. Нажимает «Проверить». Сервис анализирует адрес без перехода на указанный сайт.
4. Система показывает результат и обнаруженные основания. Пользователь показывает, что упоминание банка в адресе не подтверждает принадлежность домена банку.
5. В рекомендациях пользователь показывает официальный контакт указанного банка из справочника сервиса.
6. Результат сохраняется в аккаунте. Если вместо URL введен некорректный адрес, система предлагает исправить ввод.

### [ Сценарий 4 - Проверка ссылки из QR-кода ]

1. Пользователь выбирает «QR-код» и загружает `qr-ordinary.png`.
2. Указывает ожидаемую организацию «Альфа-Банк» и нажимает «Проверить».
3. Система извлекает адрес `https://www.alfabank.ru` и показывает результат его анализа. Пользователь показывает извлеченную ссылку и рекомендации.
4. Пользователь возвращается к форме и загружает `qr-warning.png`, указав «Сбербанк».
5. Система извлекает подозрительную ссылку и показывает предупреждение с основаниями. Переход по ссылке не выполняется.
6. Если QR не читается, кодов несколько или внутри находится не HTTP(S)-ссылка, система сообщает причину отказа.

### [ Сценарий 5 - Проверка скриншота переписки ]

1. Пользователь выбирает «Скриншот» и загружает `warning.png`.
2. Нажимает «Проверить».
3. Система распознает текст изображения и выполняет анализ переписки.
4. Пользователь показывает распознанный текст и сопоставляет его с изображением.
5. Пользователь показывает предупреждение, найденные просьбы и рекомендации: в примере речь идет о безопасном счете, секретности и коде из СМС.
6. Результат сохраняется в истории аккаунта. Поврежденный файл или неподдерживаемый формат система отклоняет с объяснением.

### [ Сценарий 6 - Загрузка и дополнение истории операций ]

1. Пользователь открывает «История операций» и показывает ссылку «Скачать шаблон с вымышленными операциями».
2. Загружает подготовленный `demo_history.csv`, оставив «Заменить всю историю» выключенным. Система показывает 20 операций.
3. В разделе «Ввести операции вручную» нажимает «Добавить строку».
4. Вводит дату `21.10.2026 12:00`, сумму `250`, направление «Списание» и контрагента `known_shop`. Нажимает «Сохранить операции».
5. Система добавляет строку: в истории становится 21 операция.
6. Пользователь снова загружает тот же CSV без галочки замены. Система добавляет все строки, включая повторы: становится 41 операция.
7. Пользователь загружает тот же CSV с галочкой «Заменить всю историю». Система заменяет данные: снова 20 операций.
8. Если CSV некорректен, система показывает ошибку и сохраняет прежнюю историю. Для записи можно выбрать [текст переписки](examples/demo/warning-chat.txt) вместо CSV и показать, что 20 операций остались на месте.

### [ Сценарий 7 - Проверка перевода с учетом личной истории ]

1. Пользователь выбирает «Перевод». В аккаунте уже есть 20 списаний из предыдущего сценария.
2. Вводит сумму `500000`, назначение «Покупка», обозначение получателя `new_shop`.
3. В анкете выбирает «Кто попросил перевод» — «Продавец», «Канал обращения» — «Чат», «Реквизиты менялись» — «Да». Остальные ответы оставляет неизвестными, текст просьбы не заполняет.
4. Нажимает «Проверить».
5. Система сравнивает сумму и получателя с личной историей и учитывает указанную смену реквизитов.
6. Пользователь показывает предупреждение и основания: сумма отличается от прежних списаний, получатель отсутствует в истории, реквизиты менялись.
7. Пользователь показывает, какие сведения указаны им самим, а какие получены сравнением с историей. Сервис не выполняет перевод; решение остается за пользователем.

### [ Сценарий 8 - Просмотр сохраненного результата в другой сессии ]

1. Пользователь открывает «История проверок». Система показывает проверки, выполненные после входа; гостевой текст из сценария 2 в списке отсутствует.
2. Пользователь открывает проверку перевода из сценария 7 и показывает сумму, дату и результат.
3. Переходит в «Аккаунт» и нажимает «Выйти».
4. Открывает сайт в другом браузере или новом приватном окне и входит с теми же логином и паролем.
5. Открывает «История проверок» и выбирает ту же проверку перевода.
6. Система показывает ранее сохраненный результат без повторного анализа. Данные хранятся в аккаунте и доступны в новой сессии.

### [ Сценарий 9 - Отзыв и отдельное согласие на использование данных ]

1. Пользователь остается на странице своей проверки перевода и открывает блок «Чем закончилась ситуация».
2. Выбирает исход «Неизвестно», вводит комментарий «Демонстрационный отзыв» и нажимает «Сохранить отзыв».
3. Система сохраняет отзыв. Пользователь меняет исход на «Обычная ситуация» и снова сохраняет: отзыв обновляется, а исходное предупреждение остается прежним.
4. Пользователь открывает условия в блоке «Использование данных для будущего обучения».
5. Отмечает разрешение использовать данные этой проверки и нажимает «Сохранить решение».
6. Система подтверждает действующее согласие. Пользователь обновляет страницу и показывает, что отзыв и согласие сохранены.
7. Пользователь снимает флажок и снова нажимает «Сохранить решение». Система показывает, что действующего согласия больше нет; отзыв остается сохраненным.
8. Разрешение относится только к выбранной проверке. Сохранение отзыва или согласия не запускает обучение модели.
