# Альфа Защита

Веб-сервис для проверки текста, ссылок, аудиозаписей, скриншотов переписки и обстоятельств предполагаемого перевода. Русский язык, платежи в рублях, пользователи в РФ.

**На 4 ноября 2026 года подготовлены основа Django, аккаунты, формы, хранение и завершение проверок, CSV, отзывы и отдельное согласие на обучение.** HTTP подключен для аккаунтов, своей истории, результатов, CSV и отзывов; используются простые шаблоны. Есть лимит входа. Локально работает PostgreSQL 17.11, проходят 182 тестовых случаев; GitHub Actions настроен. Офлайн реализованы текст и URL: для текста механизм проверен на демонстрационном наборе, для URL CatBoost обучен на PhiUSIIL и проверен на validation с отдельными доменами. Независимое качество на свежих данных ещё не измерено. Главная и формы пяти режимов подключены. Формы текста, ссылки и перевода подключены к Analyzer при настроенном комплекте моделей; без него ввод не сохраняется. Загрузки аудио и скриншотов выключены. Подготовлен запуск через Gunicorn; провайдер и публичное размещение пока отсутствуют. Оформление еще не выполнено. Разработка с нуля на Django + Django Templates + PostgreSQL.

## Запуск и проверка

Зависимости уже установлены в рабочий venv, локальный `.env` создан и исключён из Git. Проверка настроек из корня проекта:

```bash
source /Users/Shared/github/MachineLearning/ml_venv/bin/activate
python manage.py check
```

Установка зависимостей по lock-файлу без очистки общего venv:

```bash
uv export --locked --no-dev --no-emit-project --format requirements-txt --output-file /tmp/alphago1v-requirements.txt
uv pip install --python "$VIRTUAL_ENV/bin/python" -r /tmp/alphago1v-requirements.txt --require-hashes
```

Перед этими командами нужно активировать venv как показано выше. На другой машине также нужен `.env` по примеру `.env.example` с собственными секретами.

PostgreSQL запускается через `compose.yaml`. На текущем компьютере выполнены запуск БД и применение миграций. После установки Docker команды из корня проекта:

```bash
docker compose up -d --wait db
python manage.py migrate --noinput
python -m pytest -q
```

Если Docker ещё не добавлен в PATH, на macOS команды находятся внутри `/Applications/Docker.app/Contents/Resources/bin/`, а Compose — в `Resources/cli-plugins/docker-compose`.

Тестовые зависимости входят в группу `dev`. Для установки вместе с ними в приведенной команде `uv export` убираем `--no-dev`. После запуска PostgreSQL тесты выполняются командой `python -m pytest -q`. GitHub Actions запускает их на PostgreSQL 17 при push и pull request, предварительно проверяя настройки и миграции.

Для локальной проверки аккаунтов после запуска БД и миграций:

```bash
python manage.py runserver
```

Откройте `http://127.0.0.1:8000/accounts/register/` или `/accounts/login/`. После входа `/accounts/` ведет на `/checks/` и `/transactions/`. Можно открыть свою сохраненную проверку, оставить отзыв, изменить отдельное согласие, скачать шаблон, импортировать или удалить свою историю операций. Главная `/` ведет на `/checks/new/<kind>/`. При настроенном ANALYZER_DIR формы текста, ссылки и перевода выполняют анализ: аккаунт получает сохраненную проверку, гость — временный ответ. Без готового комплекта возвращается 503 без сохранения; медиа отключены до подключения распознавания и лимитов. Пять неверных попыток входа с одного IP за 15 минут включают отказ 429. Это локальный сервер разработки, не команда публичного размещения.

## Текстовая модель

Общий вход — `analysis.features.Turn`: текст, ID реплики, необязательный говорящий и место в исходном материале. `analysis.text.TextModel` обучает семь классификаторов поверх замороженного E5. На выходе — текущие и предыдущие оценки с источниками; итоговая опасность и подключение к HTTP остаются следующими блоками.

Технический запуск на [14 демонстрационных примерах](examples/text_train.jsonl):

```bash
uv run --isolated --locked --group ml --no-dev python -m ml.train_text examples/text_train.jsonl var/ml/text-demo --download
```

Группа `ml` добавляет PyTorch и Transformers. Изолированное окружение использует lock-файл и сохраняет общий venv других проектов. `--download` явно разрешает первое скачивание закреплённого E5; затем используется кэш `var/ml/cache`. Результат сохраняется в новую папку: существующая не перезаписывается. Веса и обучающие артефакты исключены из Git.

JSONL содержит `case_id`, `group_id`, `split`, `turns`, `target_turn_id`, `fragment_id`, семь `labels` и семь `evidence` в порядке `TEXT_LABELS`. Метки — 0/1/null; положительная цитата должна находиться в целевом фрагменте. Для собственной независимой validation используется `--validation путь.jsonl` со `split=validation`, без общих групп и случаев с train. `test` и `calibration` не принимаются как обучающий файл.

Демонстрационная разметка синтетическая и не проверена независимо; её прогнозы не являются готовым анализом мошенничества. Источники рабочего корпуса, разбиение и дальнейшее обучение: [ML_PLAN.md](ML_PLAN.md). Обычный CI запускает тесты без скачивания E5; реальный ML-прогон проверяется отдельно.

## URL-модель

`analysis.url.URLModel`: 12 признаков строки → CatBoost; отдельно проверяется соответствие бренда подтверждённым доменам. Проверяемые сайты не открываются. На выходе — оценки, маски доступности и адреса-источники для будущего итогового дерева. HTTP использует этот блок через общий Analyzer при настроенном комплекте.

Подготовка [PhiUSIIL, UCI](https://archive.ics.uci.edu/dataset/967/phiusiil+phishing+url+dataset), CC BY 4.0, и обучение:

```bash
python -m ml.prepare_urls var/ml/urls/new-data --download
python -m ml.train_url var/ml/urls/new-data/train.jsonl var/ml/url-new --validation var/ml/urls/new-data/validation.jsonl --source-manifest var/ml/urls/new-data/source_manifest.json
```

Команды используют активированный venv с основными зависимостями, без группы `ml`. ZIP скачивается только по явному флагу; его SHA-256 проверяется. Используются только исходный URL и метка, без готовых HTML-признаков. Дубли удаляются, зарегистрированные домены не пересекаются между частями. Выходные папки должны быть новыми; данные и артефакты находятся вне Git в `var/`.

Текущий артефакт: `var/ml/url-01`. Train — 172086 адресов, validation — 19662; F1 0.992975 при диагностическом пороге 0.5. Это результат данного корпуса, не оценка свежих реальных ссылок. Calibration и test не оценивались. Параметры, остальные метрики и ограничения — в [ML_PLAN.md](ML_PLAN.md).

## Признаки перевода

`analysis.transfer.transfer_features` считает 10 числовых признаков суммы и исходящей истории; неизвестные значения остаются None для общего сборщика масок. Отдельная модель здесь не обучается. Форма перевода принимает пять вопросов с фиксированными ответами и unknown по умолчанию, без свободного пересказа; оригинальную просьбу можно добавить отдельно. Итоговое дерево и анализ через сайт ещё не подключены.

## Вход итогового дерева

`analysis.risk.risk_features` собирает 105 фиксированных входов из одной целевой реплики, URL, перевода и анкеты. Использует существующий сборщик чисел и масок; сохраняет источники отдельно. Полный список и порядок — `RISK_FEATURES`, версия — `risk-input-v1`. RiskModel обучает дерево по готовым признакам, возвращает класс и условия пути, сохраняет и загружает артефакт. При плохом распознавании или повышенном риске только из-за пропусков общий класс не выдается. Механизм проверен на искусственных тестовых данных; рабочего risk-корпуса, OOF-подготовки и обученной для сайта модели ещё нет. HTTP использует общий Analyzer при настроенном комплекте.

## Итоговый ответ

`analysis.result.assemble_result` объединяет готовые решения дерева, добавляет признаки с источниками, советы и ограничения. Пороги показа передаются явно после калибровки, значения 0.5 по умолчанию нет. Нулевая оценка части диалога не объявляется нулевым итогом всего материала; статусы распознавания и достаточность хранятся отдельно. Составная версия учитывает блоки и пороги. Общий запуск уже связан через Analyzer и run_check; веб-страницы вызывают его через локальный загрузчик при настроенном комплекте моделей.

## Общий запуск анализа

`analysis.pipeline.Analyzer` связывает текст, URL, признаки перевода, дерево и итоговый ответ. Получает готовые модели и пороги. Для диалога ссылки берутся из текущей реплики и прошлого того же известного участника; BACKGROUND не становится отдельной целью. Медиа можно передать только как уже подготовленные Turn, распознавание ещё не реализовано.

`checks.services.run_check` создает проверку, передает только свою историю аккаунта и завершает результатом либо ошибкой. Время расчета — created_at проверки. Гостевой результат остается в памяти, личного контекста у гостя нет; в аккаунт сохраняются производные признаки вместо полного CSV. HTTP и локальный загрузчик подключены. Подготовка рабочего комплекта и медиа остаются следующими шагами.

## Загрузка моделей и веб-анализ

`ANALYZER_DIR` задает каталог с text/, url/, risk/ и calibration.json. `analysis.runtime.load_analyzer` сверяет восемь порогов и версии трех моделей, загружает E5 только из локального кэша и переиспользует комплект на процесс. Подготовка каталога и зависимости группы ml описаны в [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

Корректный POST запускает run_check: аккаунт перенаправляется к сохраненному результату, гость видит временную страницу без записи и сессии. GET, неверный ввод и просмотр истории модели не запускают. Признаки и источники экранируются; нулевой риск отличается от неизвестного. Рабочего комплекта текста/дерева с калибровкой пока нет; он не заменяется демонстрационными данными автоматически.
