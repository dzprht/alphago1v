# Альфа Защита

Веб-сервис для проверки текста, ссылок, аудиозаписей, скриншотов переписки и обстоятельств предполагаемого перевода. Русский язык, платежи в рублях, пользователи в РФ.

На 5 ноября реализованы F01–F09: аккаунт, пять проверок, CSV и ручной ввод истории, сохраненные результаты, отзывы и отдельное согласие. Все пять режимов проверены через сайт с реальными локальными моделями и CSRF. В аккаунте результаты сохраняются; гостевые проверки не попадают в БД.

Анализ: rubert-tiny2, символьная URL-CNN, Whisper small, pyannote community-1 и EasyOCR ru/en. Перевод использует анкету и статистику истории; предупреждения формируют явные правила. Веса передаются отдельно от Git. Подготовка — [SELECTED_MODELS](docs/SELECTED_MODELS.md), [Whisper](docs/WHISPER.md), [диаризация](docs/DIARIZATION.md), [OCR](docs/OCR.md).

Подготовлены Nginx, systemd, проверка моделей и резервное копирование. Выбран AdminVPS VPS Standart; домен и сервер еще оформляются. Публичное размещение и скорость на VPS не проверены. [Инструкция VPS](docs/VPS.md).

## Запуск и проверка

Python 3.11, PostgreSQL 17, uv. Скопировать `.env.example` в `.env` и указать свои секреты. Общий venv других проектов не синхронизировать; установить зависимости в отдельную `.venv`:

```bash
uv sync --locked --group ml --group media
docker compose up -d --wait db
uv run --no-sync python manage.py migrate --noinput
uv run --no-sync python manage.py collectstatic --noinput
```

Передать выбранные RuBERT/CNN в `var/ml/selected-models`, подготовить три медиаблока по ссылкам выше и добавить media.json по `examples/media.json`. Указать `ANALYZER_DIR=var/ml/selected-models`. Веса не скачиваются через веб-запросы и не входят в обычный git pull.

```bash
uv run --no-sync python manage.py check_models
uv run --no-sync python manage.py runserver
```

`check_models` требует полный комплект, включая диаризацию. Все пять форм находятся на главной; аккаунт, история и импорт — в навигации. Временный guest-результат не переносится автоматически в аккаунт.

Основные тесты и отдельный сквозной тест с настоящими весами:

```bash
uv run --no-sync pytest -q --ignore=tests/test_benchmark_notebook.py
NATIVE_MODELS_DIR=var/ml/selected-models uv run --no-sync pytest -q tests/test_native_site.py
```

Без NATIVE_MODELS_DIR тяжелый тест пропускается явно. Обычный GitHub Actions проверяет логику на PostgreSQL без скачивания весов. Сквозной тест использует отдельную тестовую БД и проходит F01–F09, CSRF, отзыв согласия и статистику перевода. Это проверка работоспособности, не независимое измерение качества моделей.

Локально: 314 основных тестов прошли; тяжелый сквозной тест отдельно прошел с полным комплектом. Проверены конфигурации Nginx/Gunicorn и восстановление дампа в отдельную PostgreSQL.

## Текстовая модель

Общий вход — `analysis.features.Turn`: текст, ID реплики, необязательный говорящий и место в исходном материале. Выбранный `RuBERTModel` получает фрагмент и контекст, возвращает семь оценок. Максимумы и источники собирает прежний `TextModel.predict`. Ниже сохранена команда обучения старого варианта E5 + семь LR.

Технический запуск на [14 демонстрационных примерах](examples/text_train.jsonl):

```bash
uv run --isolated --locked --group ml --no-dev python -m ml.train_text examples/text_train.jsonl var/ml/text-demo --download
```

Группа `ml` добавляет PyTorch и Transformers. Изолированное окружение использует lock-файл и сохраняет общий venv других проектов. `--download` явно разрешает первое скачивание закреплённого E5; затем используется кэш `var/ml/cache`. Результат сохраняется в новую папку: существующая не перезаписывается. Веса и обучающие артефакты исключены из Git.

JSONL содержит `case_id`, `group_id`, `split`, `turns`, `target_turn_id`, `fragment_id`, семь `labels` и семь `evidence` в порядке `TEXT_LABELS`. Метки — 0/1/null; положительная цитата должна находиться в целевом фрагменте. Для собственной независимой validation используется `--validation путь.jsonl` со `split=validation`, без общих групп и случаев с train. `test` и `calibration` не принимаются как обучающий файл.

Демонстрационная разметка синтетическая и не проверена независимо; её прогнозы не являются готовым анализом мошенничества. Источники рабочего корпуса, разбиение и дальнейшее обучение: [ML_PLAN.md](ML_PLAN.md). Обычный CI запускает тесты без скачивания E5; реальный ML-прогон проверяется отдельно.

## URL-модель

Справочник ожидаемых организаций расширен до 63 записей и 165 доменов. Названия предлагаются в форме проверки ссылки. Источники, ограничения и обновление уже сохраненных моделей: [BRAND_CATALOGUE.md](docs/BRAND_CATALOGUE.md).

Выбранный `CNNModel` оценивает исходные символы URL; прежний `URLModel.predict` проверяет домены и собирает источники. Проверяемые сайты не открываются. Ниже сохранены команды обучения старого CatBoost по 12 признакам строки.

Подготовка [PhiUSIIL, UCI](https://archive.ics.uci.edu/dataset/967/phiusiil+phishing+url+dataset), CC BY 4.0, и обучение:

```bash
python -m ml.prepare_urls var/ml/urls/new-data --download
python -m ml.train_url var/ml/urls/new-data/train.jsonl var/ml/url-new --validation var/ml/urls/new-data/validation.jsonl --source-manifest var/ml/urls/new-data/source_manifest.json
```

Команды используют активированный venv с основными зависимостями, без группы `ml`. ZIP скачивается только по явному флагу; его SHA-256 проверяется. Используются только исходный URL и метка, без готовых HTML-признаков. Дубли удаляются, зарегистрированные домены не пересекаются между частями. Выходные папки должны быть новыми; данные и артефакты находятся вне Git в `var/`.

Прежний артефакт CatBoost: `var/ml/url-01`. Train — 172086 адресов, validation — 19662; F1 0.992975 при диагностическом пороге 0.5. Это результат данного корпуса, не оценка свежих реальных ссылок. Параметры выбранной CNN и ограничения — в [ML_PLAN.md](ML_PLAN.md).

## Признаки перевода

`analysis.transfer.transfer_features` считает 10 числовых признаков суммы и исходящей истории; неизвестные значения остаются None для общего сборщика масок. Отдельная модель здесь не обучается. Форма перевода принимает пять вопросов с фиксированными ответами и unknown по умолчанию, без свободного пересказа; оригинальную просьбу можно добавить отдельно. H/N передаются правилам предупреждений; дерево для новых проверок не используется.

## Предупреждения и общий запуск

Новые проверки используют явные правила, без итогового дерева и классов риска. Баннер: `C or P or R or F or (M and (U or S or A)) or (D and (H or N))`. H+N без смены реквизитов остаются замечаниями. Полная таблица, неизвестные значения и источники: [WARNING_POLICY.md](docs/WARNING_POLICY.md).

`Analyzer.prepare` собирает признаки; `analyze` применяет правила. `run_check` передает только свою историю аккаунта, сохраняет результат и производные показатели без полного CSV. У гостя история не используется. HTTP-медиа подключены через временные файлы и отдельно настроенные локальные распознаватели; после обработки или ошибки файлы удаляются. Старые сохраненные результаты открываются без пересчета.

`ANALYZER_DIR` указывает на выбранный комплект с MANIFEST.json, thresholds.json, rubert/, fragment_tokenizer/ и url_cnn/. Старый формат text/, url/ и calibration.json тоже поддерживается. Дерево не требуется. Загрузчик проверяет целостность и использует только локальные веса. Без комплекта POST дает 503 без создания проверки. Подготовка запуска: [DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Подготовка обучения и медиа

`analysis/audio.py`: Whisper + необязательный pyannote → слова, говорящие и реплики. Whisper проверен на двух постановочных записях и тишине; pyannote — на одном голосе и постановочном A/B/A. `analysis/screenshot.py`: EasyOCR → рамки, пузыри и стороны. HTTP вызывает локальные адаптеры через load_media_model; все веса подготовлены локально и проверены в общем сквозном тесте. Геометрия пузырей пока прототип, поддержка оформления всех мессенджеров не подтверждена.

Команды прежнего исследования E5/LR и CatBoost сохранены в `ml/`: OOF, обучение дерева, получение оценок и калибровка. Они не переобучают выбранные RuBERT/CNN. Форматы и порядок команд — [docs/ML_WORKFLOW.md](docs/ML_WORKFLOW.md). Тяжелые зависимости выделены в группы `ml` и `media`; основной CI проверяет логику с подставными распознавателями.

## Интерфейс

Страницы используют `templates/base.html`, общий вывод полей `templates/includes/form_fields.html` и `static/css/site.css`. Небольшой `static/js/transactions.js` добавляет строки ручного ввода без перезагрузки; без JavaScript работает серверная кнопка. Кнопки, ошибки, результаты, история, CSV и аккаунты оформлены одинаково; таблица имеет отдельную прокрутку на телефоне. WhiteNoise отдает собранные CSS и JS при DEBUG=False; порядок сборки — в [DEPLOYMENT.md](docs/DEPLOYMENT.md). Формы аудио и скриншотов принимают файлы; доступность распознавания зависит от локальных весов и media.json.

## Загрузка медиа — 5 ноября

Аудио: WAV PCM16, 16000 Гц, один или два канала, до 60 секунд и 4 МиБ. Скриншот: статический PNG/JPEG, до 5 МиБ и 4 млн пикселей. Проверяется содержимое, не только расширение. Исходные файлы обрабатываются в TemporaryDirectory и удаляются после успеха или ошибки; извлеченный текст сохраняется только в проверке аккаунта, гостевой результат остается временным. Поля ручного описания участников удалены.

Настройка локальных распознавателей: [MEDIA.md](docs/MEDIA.md). Готовые постановочные примеры и порядок показа: [DEMO.md](docs/DEMO.md). Постановочные примеры проходят формы и общий анализ с настоящими весами; качество на реальных разговорах и любых мессенджерах этим не доказано.
