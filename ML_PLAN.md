1 ноября 2026. Офлайн реализованы текст и URL. Текстовый E5 и семь LR проверены на 14 демонстрационных примерах; рабочий текстовый корпус и независимая оценка ещё не подготовлены. URL CatBoost обучен на PhiUSIIL и проверен на validation с отдельными доменами; calibration/test ещё не оценивались. Итоговое дерево, медиа и HTTP-интеграция не реализованы. Объём — F02–F06 из [SPECIFICATION.md](SPECIFICATION.md). Стартовые параметры проверяем на validation; итоговую конфигурацию фиксируем до test.

2 ноября добавлены офлайн-признаки перевода в `analysis/transfer.py` и анкета в `TransferCheckForm`. Это детерминированные расчеты для будущего дерева, не отдельный обучаемый классификатор. Итоговая оценка и HTTP-интеграция анализа пока отсутствуют.

## 1. Цели и состав

- Текст: multi-label распознавание **7 признаков** в целевой реплике с контекстом.
- URL: отдельная бинарная классификация `phishing=1 / benign=0`.
- Итог: опасность выполнения описанного действия, `risk=0/1/2`: явных признаков не обнаружено / есть основания насторожиться / выраженная опасность. Это экспертная оценка, не подтверждённый исход fraud.
- Достаточность `sufficient / limited / insufficient` и техническая ошибка — отдельные поля, не классы риска.

Правила risk-разметки: `0` — обычное действие без наблюдаемых оснований насторожиться; `1` — существенные сомнения, требующие независимой проверки; `2` — выраженно опасная инструкция, например передать секрет собеседнику или перевести деньги для их «защиты». При недостаточности для экспертного выбора — null, а не автоматически `0` или `1`. Аннотатор оценивает весь доступный сценарий, а не сумму cue-меток.

| Блок | Архитектура | Обучаем |
| --- | --- | --- |
| Текст | Замороженный `intfloat/multilingual-e5-small` → 7 независимых `LogisticRegression` | Только классификаторы признаков |
| URL | `CatBoostClassifier`, 400 итераций, depth=5, learning_rate=0.05, Logloss | Весь классификатор на признаках строки |
| Аудио | `Systran/faster-whisper-small`, CPU int8, ru + `pyannote/speaker-diarization-community-1` | Нет |
| Скриншот | EasyOCR ru/en: CRAFT + `cyrillic_g2`; отдельная обработка пузырей и сторон | Нет; обработку интерфейса реализуем сами |
| Итог | `DecisionTreeClassifier`, max_depth=5, min_samples_leaf=25 | Дерево на явных признаках и метках риска |

Для обучаемых классификаторов: `random_state/random_seed=42`, балансировка классов по train. Для LR: L2, C=1, max_iter=1000; для дерева — criterion=gini. Генеративной модели при проверке пользователя нет.

## 2. Данные и разметка

| Источник | Использование |
| --- | --- |
| [dokster RU/EN](https://huggingface.co/datasets/dokster/adaption-scam-dataset-ru-en-v1) | Очищенные сообщения; собственная разметка признаков. Корпус синтетический, русские строки переводные. Инструкции и ответы ассистента исключаем из входа. |
| [Smishing IMC25](https://github.com/reportsmishing/Smishing-Dataset-IMC25) | Отобранные сообщения из реальных пользовательских отчётов; EN и проверенные переводы RU. Существующие метки не заменяют наши 7 меток. |
| [Telegram spam](https://huggingface.co/datasets/alt-gnome/telegram-spam) | Отобранные обычные русские сообщения, дополненные обычными финансовыми обращениями. Spam не приравниваем к fraud. |
| Собственная синтетика RU/EN | Ориентир — до 10 тыс. сообщений и диалогов после проверенного пилота. Разные сценарии, участники, формулировки, сочетания признаков, обычные просьбы, отрицания и цитаты. |
| [PhiUSIIL](https://archive.ics.uci.edu/dataset/967/phiusiil+phishing+url+dataset) | Обучение URL по `URL` и метке; исходное `label=0` преобразуем в наше `phishing=1`. Остальные готовые колонки не используем. |
| [DeepURLBench](https://github.com/deepinstinct-algo/DeepURLBench) | Ограниченная независимая выборка `urls_without_dns`, только phishing/benign, с датами. Не используем при подборе модели. |
| Собственные целые сценарии | Текст/URL/анкета/история в согласованной ситуации + отдельно размеченный `risk`. Связанные записи для обучения итогового дерева. |
| Собственные записи и скриншоты | Ручные расшифровки, участники и порядок реплик; проверка ASR/OCR и полных цепочек. Голоса и интерфейсы test не повторяют обучающие постановки. |

Общие поля: `case_id, source, language, group_id, turns, input_fields, history, annotation_origin`. Текстовая обучающая строка: `target_turn_id, fragment_id, labels[7], evidence[7]`; строка итоговой задачи: `target_turn_id, risk` — одна на целевую реплику, а у URL/перевода одна на проверку, в том числе без текста. `labels`: 1/0/null; `risk`: 0/1/2/null. Положительная метка требует дословного фрагмента; неизвестная — без выдуманной цитаты. Храним лицензию, версию и происхождение производных.

Codex размечает и генерирует обучение; человек проверяет пилот, спорные случаи и независимый тест. После генерации проверяем фактические метки текста, а не копируем заданные генератору условия. Неизвестные метки исключаем только из соответствующей задачи. Итоговый риск размечаем по ситуации, **не вычисляем суммой признаков**. Случайно соединённые история и сообщение не становятся размеченным сценарием. Синтетический итог проверяет воспроизведение экспертной оценки, не реальную вероятность мошенничества.

## 3. Текстовые признаки и вход энкодера

| Код | Положительная метка |
| --- | --- |
| `urgency` | Подталкивают действовать немедленно |
| `money_request` | Просят заплатить или перевести деньги |
| `credentials_request` | Просят раскрыть код подтверждения, пароль или платёжные данные |
| `secrecy` | Требуют скрыть происходящее от других |
| `remote_access` | Просят установить ПО или предоставить удалённый доступ |
| `authority_claim` | Представляются сотрудником организации или официальным лицом; подлинность не устанавливается |
| `protective_transfer` | Просят перевести деньги под предлогом их защиты, проверки или разблокирования |

Седьмой признак уточняет прежние шесть: без него просьба вернуть долг и перевод «на безопасный счёт» могут иметь одинаковый набор меток. Все признаки описывают содержание, а не доказывают fraud. Предупреждение «не сообщайте код» не размечается как просьба раскрыть код; цитирование не приписывается автору как его собственный призыв.

1. Представление: `turn_id, speaker=A/B/None, owner=user/other/unknown, text, source_span`. Одиночный текст — одна реплика. Неизвестный говорящий в коде задаётся None; участников не угадываем. При неизвестном порядке межрепликовый контекст не используем.
2. Каждую реплику делим по токенизатору E5 на фрагменты до 256 токенов с перекрытием 64; сохраняем исходные смещения. Все фрагменты обрабатываются. Метки фрагментов привязываем к их собственному содержимому, не наследуем все метки длинного диалога.
3. Для фрагмента строим два текста: сам фрагмент с говорящим; окно из него и не более четырёх предыдущих реплик. Общий лимит окна — 512 токенов с префиксом и служебными токенами; при переполнении удаляем старейший контекст, не целевой фрагмент. Последующие раскрытия исхода в окно не входят.
4. Для обоих входов: `query: `, mean pooling, L2-нормализация. Получаем два вектора по 384; конкатенация **768 → 7 LR → 7 оценок**. RU и EN кодируются одной моделью без замены слов и векторов.
5. Свободные обстоятельства F02–F05 обозначаем как `BACKGROUND` только в контекстном окне; не анализируем как отдельную чужую реплику. У перевода вместо пересказа — анкета; его оригинальная просьба остаётся текстовым входом.
6. Для итоговой оценки целевой реплики используем максимум по её фрагментам и отдельно максимум по предыдущим репликам того же известного участника: **7 текущих + 7 предшествующих оценок**. При неизвестном говорящем объединяем только фрагменты одной реплики. Сохраняем источник каждого максимума.

Объяснение ссылается на исходную реплику/фрагмент. Точную подсветку причины внутри реплики классификаторы не возвращают; коэффициенты и внимание за такую разметку не выдаём.

## 4. Аудио и изображение

**Аудио:** faster-whisper с VAD и временем слов → pyannote с интервалами говорящих → сопоставление по времени → реплики → текстовый блок. Слово получает говорящего только при однозначном пересечении с одним голосом; иначе `speaker=None`. Участников в изолированных каналах обрабатываем отдельно. A/B не определяет владельца голоса; `owner=unknown`. Одновременную речь не считаем надёжно разделённой.

**Изображение:** EasyOCR `paragraph=False` → рамки текста → группировка внутри пузырей → порядок сверху вниз → стороны A/B. Автор определяется по пузырю, не по началу отдельной строки. Принимаем личные чаты любых мессенджеров; неизвестное оформление даёт неизвестные стороны, а не выдуманное авторство. При неоднозначном порядке обработка считается частичной. Пользователь ничего не исправляет и не подтверждает вручную.

Общий контракт: `status=ok/partial/empty/error`, `turns[]`, исходные интервалы/рамки, маски порядка, говорящего и владельца. Ошибка → технический отказ; пустой текст → insufficient; partial → limited. При partial отрицательный итог не публикуем как оценку всего материала: показываем найденные признаки и недостаточность для общего вывода. Пороги пригодности распознавания и лимиты медиа выбираем на calibration по размеченным медиа до публичного включения; сырой OCR/ASR score не считается вероятностью правильности.

## 5. URL

Реализовано в `analysis/url.py`, подготовка и обучение — `ml/prepare_urls.py`, `ml/train_url.py`. Только строка; без HTTP, DNS, WHOIS и раскрытия редиректов. Разбор через urlsplit, IDNA UTS46 и Public Suffix List из пакета tldextract без сетевого обновления. Hostname — ASCII в нижнем регистре без завершающей точки; IP приводится к стандартному виду. Группировка по ICANN-доменам: все поддомены github.io остаются вместе; private suffixes отключены. Хеш PSL и версии обработки входят в артефакт.

**12 входов CatBoost:** `url_length, host_length, path_length, query_length, host_label_count, host_digit_fraction, host_hyphen_count, query_parameter_count, uses_https, host_is_ip, has_userinfo, host_has_punycode`. Длины — число символов: URL без внешних пробелов, путь и query из исходной строки, hostname после нормализации. host_label_count — число частей hostname; query_parameter_count включает повторные параметры и пустые значения, но игнорирует пустые поля между &&. Доля цифр считается по нормализованному hostname. Выход — `url_score`, оценка класса phishing, не вероятность опасности всей ситуации.

**Ручной блок:** версия справочника `название/алиасы → официальные домены` с источником каждой записи. По известной ожидаемой организации либо её названию в hostname считаем `brand_comparison_available, brand_mismatch`; совпадение проверяется по настоящему домену или его поддомену, не по подстроке URL. Без распознанного бренда сравнение неизвестно. HTTPS и punycode сами по себе опасность не доказывают. Поддерживаем проверенные алиасы; произвольное текстовое название организации не подтверждает её подлинность.

Несколько полных URL в тексте/скрине обрабатываем отдельно; адреса после ASR не достраиваем из произнесённых слов. Для итогового входа — максимальный `url_score`, any brand_mismatch, any has_userinfo, any host_is_ip и ссылки на соответствующие адреса. Недостоверно распознанный URL отмечается отдельно.

Текущий справочник `analysis/brands.json`: Альфа-Банк, Сбербанк, ВТБ; домены подтверждены карточками Банка России на 1 ноября. Ожидаемое имя, hostname или полный адрес сопоставляются только с этим справочником. Неизвестное сравнение остаётся null. Несовпадение не доказывает мошенничество.

Первый прогон: 235795 исходных строк, удалены 425 дублей и 5 некорректных адресов. SHA-256 домена с seed=42 задаёт группы 70/10/10/10; train/validation/calibration/test: 172086/19662/21537/22080 строк. Обучение только на train. На validation при диагностическом пороге 0.5: average precision 0.995595, recall 0.987009, F1 0.992975, FPR 0.000444. Calibration/test не оценивались; пороги выдачи и независимый DeepURLBench остаются впереди. Доменное разделение не гарантирует независимость кампаний и источников сбора. Артефакт: `var/ml/url-01`, вне Git.

## 6. Перевод и история

Вход: положительная сумма RUB, назначение из текущих шести вариантов, необязательный стабильный ID получателя и оригинальная просьба. Анкета:

- `requester=self/acquaintance/seller/claimed_organization/other/unknown`;
- `channel=chat/call/email/website/in_person/not_applicable/other/unknown`;
- `urgency, secrecy, changed_details=yes/no/unknown`.

Анкета поступает прямо в итоговое дерево. Текстовая модель получает только оригинальную просьбу. Анкета и извлечённые признаки не перезаписывают друг друга.

Все проверки — сейчас; пользователь дату не задаёт. Загруженную историю по времени проверки не отсекаем. Для исходящего перевода берём все исходящие операции корректной CSV. Будущие даты делают исторический контекст недостоверным: не удаляем строки и не меняем CSV, персональные признаки помечаем недоступными. В историческом эксперименте используются только предшествующие операции.

Пусть `A` — сумма в рублях, `n` — число исходящих, `k` — число исходящих с заполненным получателем, `r` — число точных совпадений получателя.

**10 числовых признаков:** `log1p(A)`, `log1p(n)`, период между первой и последней исходящей в днях, давность последней исходящей, доля сумм `≤ A`, `log(A/median)`, `k/n`, `log1p(r)`, `r/k`, давность последнего перевода этому получателю. Денежные сравнения — в целых копейках, медиана — Decimal; логарифмы — производные признаки. Все давности рассчитываются от одного UTC-момента начала проверки; дни = секунды/86400.

Медиана и перцентиль доступны при `n≥20` — стартовый порог, проверяемый на validation. Факт прошлого совпадения получателя доступен и на короткой истории. Для каждого из 10 значений есть отдельная маска `available`; дополнительно — `history_loaded, history_valid, recipient_provided`. При `n=0`, `k=0` или `r=0` соответствующие деления/давности не вычисляем. При неизвестном получателе `r` тоже неизвестно. Нулевое совпадение означает отсутствие в доступной истории, а не доказанно нового человека. Назначения в CSV нет.

В коде: `amount_log, outgoing_count_log, history_days, last_outgoing_days, amount_percentile, amount_median_log_ratio, recipient_coverage, recipient_count_log, recipient_share, last_recipient_days`. None сохраняется до общего `feature_vector`, который добавляет маски. `history=None` означает отсутствие загрузки, `[]` — загруженный пустой контекст. Без загрузки `history_valid=None`; при любой будущей строке — 0 и все персональные значения None. При корректной истории и заданном получателе `log1p(r)=0` доступен даже при `n=0` или `k=0`: это число точных совпадений, не вывод о новизне.

## 7. Итоговая модель и ответ

**Один фиксированный вектор дерева:**

- 7 текущих и 7 предыдущих текстовых оценок + маски доступности каждого значения;
- `url_score`, brand_mismatch, has_userinfo, host_is_ip + маски URL и сравнения бренда;
- 10 числовых признаков истории/суммы + их маски и 3 дополнительных флага из §6;
- one-hot `mode, purpose, requester, channel, urgency, secrecy, changed_details` с явным unknown;
- one-hot статуса извлечения и маски доступности порядка, говорящего и владельца.

Сырые тексты, эмбеддинги, ID людей/получателей и названия источников в дерево не подаём. Недоступное числовое значение технически заменяем нулём **вместе с маской**. Плохое распознавание не является признаком мошенничества.

Цель дерева — `risk` целевой просьбы с контекстом; у URL — опасность перехода, у перевода — выполнения предложенного перевода. Дерево вызываем один раз на реплику после объединения фрагментов; итог диалога — максимальный риск реплик. Итоговую разметку диалога проверяем отдельно. У URL/перевода один вызов на проверку; сопроводительное сообщение/оригинальную просьбу считаем одной целевой репликой, при длине делим на фрагменты. Без текста его маски выключены; фиктивной реплики нет.

Ответ: `risk, sufficiency, findings[], recommendations[], limitations[], analyzer_version`. Findings содержат обнаруженные признаки и источники; неподтверждённый сигнал называем предположением модели. Решение объясняем условиями пути дерева; рекомендации выбираем по шаблонам. Если повышенный итог основан только на неизвестности/качестве извлечения, выдаём insufficient без риск-класса. Проценты мошенничества не показываем.

## 8. Обучение и контроль

1. **Подготовить и разделить исходники.** Группы диалогов, кампаний, шаблонов и доменов разделить приблизительно 70/10/10/10 на train/validation/calibration/test, seed=42. Все переводы, перефразирования, медиа и связанные сценарии наследуют исходную группу. Пересечения зарегистрированных доменов между URL-частями запрещены. Сначала разбиение, затем генерация производных. Метки/ответы учителя и последующий исход в признаки не входят.
2. **Выбрать нижние параметры по validation.** E5 не обновлять; LR обучать на известных 0/1 каждой головы; CatBoost — на URL train. Проверить оба класса каждой головы, URL и все три risk-класса в нужных частях. Зафиксировать настройки нижних моделей до получения финального OOF.
3. **Получить train-входы дерева.** Пять групповых OOF-fold с зафиксированными настройками: каждую запись и её производные оценивают LR/URL-модель, не обучавшиеся на её группе/домене. В каждом обучающем fold нужны оба класса каждой головы; иначе меняем групповой расклад/число folds или дополняем данные, не разрывая группы. Внешние данные очищаем от тех же пересечений. Историю и анкету вычисляем как на сайте; для медиа используем настоящие выходы ASR/OCR.
4. **Обучить дерево** на OOF-признаках и отдельно размеченных risk; risk=null пропустить. Настройки дерева выбрать по validation; финальные LR/URL обучить на всём train. Изменение нижних параметров требует заново получить OOF и обучить дерево. Validation/calibration/test в обучение не добавлять; идеальные cue-метки вместо прогнозов не использовать.
5. **Настроить выдачу на calibration.** Пороги показа каждого текстового признака и URL выбрать по максимальному F1, при равенстве брать больший порог; проверить цитаты и отказы распознавания. Дерево получает исходные оценки, пороги меняют только findings. Отказ при техническом сбое/пустом/непригодном вводе выполняется до риск-прогноза. Нет калибровки в проценты fraud.
6. **Один итоговый test.** Для признаков: precision/recall/F1 и число известных меток; URL: PR-AUC, recall и false-positive rate; риск: macro-F1, recall уровня 2, матрица ошибок. Отдельно пять режимов, реальные/переводные/синтетические данные, короткая история и отсутствие блоков. Для медиа — WER/CER, ошибки говорящего/порядка и изменение итогового риска относительно ручной расшифровки. На выбранном сервере — память, p50/p95 задержки и лимиты. После просмотра test модель не подстраивать с сохранением названия «независимый тест».

Контрольные варианты: TF-IDF+LR для тех же текстовых меток; простые URL-правила; заранее записанные правила итоговой оценки. Если выбранная модель не даёт полезного выигрыша, пересматриваем данные/признаки на validation; обязательные F02–F06 автоматически не сокращаем.

## 9. Артефакты и границы

`ml/` — подготовка/обучение/оценка; `analysis/` — одинаковое применение на сайте и в экспериментах; `var/ml/` вне Git — данные, E5, LR, CatBoost, дерево, ASR/OCR. Manifest: версии/лицензии/хеши источников и весов, группы разбиения, порядок признаков, словари категорий/брендов, параметры, пороги и метрики. Пользовательские данные в Git не публикуем.

Отзывы F09 — непроверенные исходы, не готовые risk-метки. Будущее обучение требует отдельного действующего согласия и проверки. Автопереобучения нет; полные пользовательские CSV и исходные медиа не входят в разрешённую обучающую выгрузку.
