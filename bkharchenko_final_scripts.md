- Загрузить ролик в облако или RuTube с доступом по ссылке без VPN и проверить ссылку без входа в аккаунт.

### S01. Регистрация и вход — F01

1. Пользователь открывает страницу «Регистрация».
2. Пользователь вводит свободный логин.
3. Пользователь заполняет поля пароля и его повтора.
4. Пользователь нажимает «Зарегистрироваться».
5. Система создает аккаунт с переходом на страницу входа.
6. Пользователь вводит свой логин и пароль.
7. Пользователь нажимает «Войти».
8. Система открывает страницу аккаунта с логином пользователя.

**Ошибка:** система отклоняет занятый логин, простой пароль или несовпадающие пароли с пояснением у поля.

### S02. Проверка сообщения без регистрации — F02

1. Пользователь открывает форму «Текст» в приватном окне без входа в аккаунт.
2. Пользователь вводит: «Срочно переведите деньги на безопасный счет. Никому не говорите. Назовите код из СМС».
3. Пользователь нажимает «Проверить».
4. Система показывает предупреждение с признаками, фрагментами сообщения и рекомендациями.
5. Пользователь заменяет текст на «Привет! Завтра идем в библиотеку после уроков?».
6. Пользователь нажимает «Проверить».
7. Система показывает результат с напоминанием, что отсутствие признаков не гарантирует безопасность.
8. Пользователь закрывает приватное окно для продолжения в основном окне с аккаунтом.

**Ошибка:** система просит заполнить пустое поле текста.

### S03. Ссылка и ожидаемая организация — F03

1. Пользователь открывает форму «Ссылка» в основном окне.
2. Пользователь вводит `https://sberbank-login-security-check.example/verify`.
3. Пользователь указывает ожидаемую организацию «Сбербанк».
4. Пользователь нажимает «Проверить».
5. Система проверяет адрес на признаки поддельной ссылки.
6. Система показывает основания предупреждения, включая несовпадение с официальным доменом банка.
7. Система выводит официальный контакт банка из справочника.
8. Система сохраняет результат в аккаунте.

**Ошибка:** система предлагает исправить некорректный адрес вместо запуска проверки.

### S04. Ссылка из QR-кода — F04

1. Пользователь открывает форму «QR-код».
2. Пользователь выбирает файл `qr-ordinary.png`.
3. Пользователь указывает ожидаемую организацию «Альфа-Банк».
4. Пользователь нажимает «Проверить».
5. Система показывает извлеченную ссылку `https://www.alfabank.ru` и результат анализа.
6. Пользователь выбирает файл `qr-warning.png` в форме новой проверки.
7. Пользователь отправляет повторную проверку с ожидаемой организацией «Сбербанк».
8. Система показывает подозрительную ссылку и предупреждение с основаниями.

**Ошибка:** система отклоняет нечитаемый QR, несколько кодов или содержимое без HTTP(S)-ссылки с объяснением причины.

### S05. Скриншот переписки — F05

1. Пользователь открывает форму «Скриншот».
2. Пользователь выбирает файл `warning.png`.
3. Пользователь нажимает «Проверить».
4. Система распознает текст переписки.
5. Система проверяет распознанные сообщения на признаки риска.
6. Система показывает распознанный текст рядом с результатом.
7. Пользователь сопоставляет найденные признаки с просьбами о безопасном счете, секретности и коде из СМС на изображении.
8. Система сохраняет результат в истории аккаунта.

**Ошибка:** система отклоняет поврежденный файл или неподдерживаемый формат с пояснением.

### S06. Загрузка и дополнение истории операций — F07

1. Пользователь загружает `demo_history.csv` на странице «История операций» без отметки «Заменить всю историю».
2. Система показывает 20 операций.
3. Пользователь нажимает «Добавить строку» в разделе ручного ввода.
4. Пользователь заполняет строку: дата `21.10.2026 12:00`, сумма `250`, направление «Списание», контрагент `known_shop`.
5. Пользователь нажимает «Сохранить операции».
6. Система показывает 21 операцию.
7. Пользователь повторно загружает тот же CSV с отметкой «Заменить всю историю».
8. Система показывает 20 операций после замены истории.

**Ошибка:** система отклоняет строку с неположительной суммой с пояснением ошибки.

### S07. Перевод с учетом личной истории — F06

1. Пользователь открывает форму «Перевод» после загрузки 20 списаний.
2. Пользователь вводит сумму `500000`, назначение «Покупка» и получателя `new_shop`.
3. Пользователь заполняет анкету: «Продавец», «Чат», «Реквизиты менялись — Да»; остальные ответы неизвестны, текст просьбы пустой.
4. Пользователь нажимает «Проверить».
5. Система сравнивает сумму с прежними списаниями.
6. Система проверяет наличие получателя в личной истории.
7. Система показывает предупреждение по сочетанию нетипичной суммы, нового получателя и смены реквизитов.
8. Пользователь сопоставляет основания с пометками об источнике: собственные ответы или история операций.

**Ошибка:** система просит исправить нулевую или отрицательную сумму.

### S08. Сохраненный результат в другой сессии — F08

1. Пользователь открывает «История проверок».
2. Система показывает проверки аккаунта без гостевых результатов из S02.
3. Пользователь открывает проверку перевода из S07.
4. Система показывает сохраненные сумму, дату и результат.
5. Пользователь выходит из аккаунта.
6. Пользователь входит с теми же данными в другом браузере или новом приватном окне.
7. Пользователь открывает ту же проверку из истории.
8. Система показывает прежний результат в новой сессии.

**Ошибка:** система не показывает чужую проверку при переходе по ее адресу.

### S09. Отзыв и согласие на использование данных — F09

1. Пользователь отправляет отзыв «Неизвестно» с комментарием «Демонстрационный отзыв» на странице своей проверки.
2. Система подтверждает сохранение отзыва.
3. Пользователь сохраняет исправленный исход «Обычная ситуация» в той же форме.
4. Пользователь читает условия в блоке «Использование данных для будущего обучения».
5. Пользователь отправляет решение с отмеченным разрешением на использование данных этой проверки.
6. Пользователь обновляет страницу.
7. Система показывает сохраненные отзыв и согласие.
8. Пользователь отзывает согласие отправкой решения со снятым флажком.

**Ошибка:** система просит выбрать исход при отправке отзыва без него.
