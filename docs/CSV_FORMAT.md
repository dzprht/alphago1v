# История операций в CSV

Импорт доступен после входа. Файл должен соответствовать нашему шаблону; произвольные банковские выписки пока не поддерживаются.

Пример с вымышленными операциями: [transactions.csv](../examples/transactions.csv). При заполнении замените примеры своими строками.

## Формат

- Кодировка UTF-8; BOM допускается.
- Разделитель `;`. Заголовок и порядок колонок строго как ниже.
- Не больше 2 МиБ и 10 000 операций. Нужна хотя бы одна операция.
- Пустые строки пропускаются. Внешние пробелы значений убираются.

```csv
occurred_at;amount;direction;recipient
2026-10-20T14:30:00+03:00;1500.50;outgoing;shop_1
2026-10-21T09:00:00+03:00;30000.00;incoming;employer
2026-10-22T18:15:00+03:00;800.00;outgoing;
```

| Колонка | Обязательность и смысл |
| --- | --- |
| `occurred_at` | Обязательна. Дата и время операции в ISO 8601 с часовым поясом: например, `2026-10-20T14:30:00+03:00` или `2026-10-20T11:30:00Z`. Дата без времени и пояса не принимается. В БД хранится момент времени, приведенный к UTC. |
| `amount` | Обязательна. Положительная сумма в рублях, до 16 цифр до разделителя и двух после. Допустимы `1500`, `1500.50`, `1500,50`. Без знака, пробелов внутри числа и разделителей тысяч. Ноль и отрицательная сумма не принимаются. В коде сумма переводится в целые копейки. |
| `direction` | Обязательна. `outgoing` — списание, `incoming` — поступление. Сумма в обоих случаях положительная. Направление считается относительно владельца истории. |
| `recipient` | Колонка обязательна, значение можно оставить пустым. Условный ID контрагента, до 100 символов без переносов и управляющих знаков. Для списания это получатель, для поступления — отправитель. Например, `shop_1` или `friend_2`. |

Валюта всегда RUB, отдельной колонки для нее нет. Назначение будущего перевода вводится в форме проверки, а не в CSV.

`recipient` сопоставляется точно после удаления внешних пробелов: регистр и внутренние пробелы сохраняются. Один контрагент должен иметь одинаковый ID во всех строках и в проверке перевода. Сходство имен не объединяет людей. Номера карт и счетов для этого не нужны. Пустое значение означает неизвестного контрагента.

## Что происходит при загрузке

1. Весь файл проверяется до изменения истории. При ошибке поля указываются строка, название поля и причина; при ошибке размера или кодировки — файл и причина.
2. Корректная загрузка полностью заменяет прежнюю историю этого пользователя. Добавления к старой истории нет.
3. При ошибке файла или записи в БД прежняя история остается целой.
4. Повторная загрузка того же файла не накапливает операции. Одинаковые строки внутри файла сохраняются: это могут быть разные операции.

Исходный CSV не сохраняется приложением. В БД остаются разобранные строки, дата загрузки, число операций, период и SHA-256 файла. Хеш помогает сравнить загруженные файлы, но не доказывает подлинность выписки.

Чтение и удаление ограничены владельцем. Удаление убирает активную загрузку и ее операции, но не прежние результаты проверок.

По решению от 1 ноября проверяется предполагаемый перевод **сейчас**: отдельного поля даты нет, загруженная история по моменту проверки не отсекается. Для исходящего перевода сравниваются исходящие операции корректной истории. Непригодные даты ограничивают достоверность исторического контекста; строки молча не удаляются. Начальные признаки и минимум данных заданы в [ML_PLAN.md](../ML_PLAN.md), качество статистики ещё не проверено. Для исторических экспериментов отсечение по времени тестовой операции сохраняется.

29 октября подключена страница `/transactions/` после входа: скачивание примера, импорт, таблица и удаление своей истории. Предупреждения о замене и удалении показаны перед кнопками. Все изменения требуют POST с CSRF-токеном. Анализ перевода получает собственную историю пользователя через run_check.

## Ручной ввод

5 ноября на той же странице добавлен ввод без файла. До 100 строк: дата и время по Москве, сумма в рублях, направление «Списание» или «Поступление», необязательное обозначение контрагента до 100 символов. Дата обязательна; внутри хранится UTC. Сумма проверяется по тем же правилам и сохраняется в копейках.

«Добавить строку» добавляет поля; «Удалить» исключает строку из нового импорта. Пустые дополнительные строки не сохраняются. Добавление доступно и без JavaScript через отправку формы без записи истории. Для сохранения нужна хотя бы одна корректная неудаленная операция.

«Сохранить и заменить историю» заменяет все прежние операции введенными строками. При ошибке хотя бы одной сохраняемой строки прежняя история остается. CSV и ручная форма используют validate_transaction и replace_transactions; отдельной истории для ручного ввода нет. SHA-256 ручного импорта пустой, так как файл отсутствует.
