# Подготовка к размещению

Провайдер и аккаунт пока не выбраны. Подготовлен переносимый запуск, проверенный локально. Публичного адреса еще нет.

## Установка и запуск на хостинге

Нужен Linux-хостинг с Python 3.11. Из корня проекта, в отдельном окружении хостинга:

```bash
python -m pip install uv==0.11.7
uv sync --locked --no-dev
uv run --no-sync python manage.py migrate --noinput
uv run --no-sync gunicorn config.wsgi:application
```

Последняя команда записана в `Procfile`. Если платформа его не читает, ее нужно указать как Start Command. Миграции выполняются отдельно перед запуском, а не в каждом процессе сервера.

Gunicorn сам использует `PORT`, если его задает хостинг. Без него слушает локальный порт 8000. Отдельного файла настроек сервера нет. На общем рабочем venv не выполнять `uv sync`: эта команда здесь относится к отдельному окружению хостинга.

## Переменные окружения

Основные имена есть в `.env.example`. На хостинге секреты задаются в его панели, без загрузки рабочего `.env` в Git.

| Параметр | Значение на хостинге |
| --- | --- |
| `DJANGO_SECRET_KEY` | Отдельный случайный секрет, минимум 50 символов. |
| `DJANGO_DEBUG` | `0`. |
| `DJANGO_ALLOWED_HOSTS` | Реальные домены через запятую, без схемы и пробелов. |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_HOST`, `POSTGRES_PORT` | Параметры постоянной PostgreSQL от провайдера. |
| `PGSSLMODE` | Режим SSL клиента PostgreSQL по настройкам провайдера. В локальном примере `prefer`; для внешней БД параметры TLS выбираются отдельно. `require` шифрует соединение, `verify-full` дополнительно проверяет имя сервера и требует доверенный CA. |
| `DJANGO_HTTPS` | `1` после настройки реального HTTPS: перенаправление с HTTP и secure-cookie для сессии и CSRF. Локально `0`. |
| `FORWARDED_ALLOW_IPS` | IP доверенных прокси для Gunicorn. По умолчанию `127.0.0.1,::1`. Реальные адреса выбираются при настройке провайдера. Прокси должен удалять клиентский `X-Forwarded-Proto` и задавать достоверное значение сам; прямой доступ к серверу приложения нужно ограничить. |

Для обычных форм на том же домене отдельный `CSRF_TRUSTED_ORIGINS` не нужен. Если появятся другие разрешенные источники, добавим конкретные адреса при настройке провайдера.

Gunicorn определяет исходную схему HTTPS по заголовкам доверенного прокси и передает ее Django через WSGI. Отдельный переключатель доверия заголовку в Django не добавлен. `FORWARDED_ALLOW_IPS` управляет доверием к заголовкам схемы, но сам по себе не подставляет IP посетителя в `REMOTE_ADDR`.

`PORT` и `FORWARDED_ALLOW_IPS` задаются в окружении процесса, например в панели хостинга. Gunicorn читает их раньше, чем Django загружает локальный `.env`.

## Что остается проверить у провайдера

- HTTPS и сохранение входа в браузере; перенаправление не должно зацикливаться.
- Достоверный IP клиента для лимита входа. Пока используется `REMOTE_ADDR`; нельзя считать адрес прокси адресом всех пользователей или доверять любому присланному IP.
- Сохранность PostgreSQL после перезапуска и восстановление резервной копии. Фактическая копия и восстановление пока не проверялись.
- Сроки хранения пользовательских данных перед публичным доступом.

`check --deploy` проверен с параметрами будущего HTTPS-режима. Осталось предупреждение `security.W004`: HSTS включим после проверки HTTPS на реальном домене.

Статических файлов и Django admin сейчас нет, поэтому `collectstatic`, WhiteNoise и отдельный сервер статики не добавлены. При появлении CSS или других статических файлов способ их отдачи нужно подключить до публикации.

Анализ еще не подключен, медиа-обработка выключена. Проверка настроек не заменяет фактическую проверку сайта на хостинге.
