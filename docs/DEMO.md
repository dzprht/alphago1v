# Демонстрация аудио и скриншотов

В `examples/demo/` лежат постановочные примеры без личных данных. Они подходят по формату и размеру. Распознавание и итоговые признаки нужно проверить с подключенными весами до защиты; формат файла не гарантирует ответ модели.

| Файл | Содержание | Формат и размер |
| --- | --- | --- |
| `warning.png` | Переписка: перевод на безопасный счет, секретность, запрос кода | PNG RGB, 720×600, около 28 КБ |
| `ordinary.png` | Договоренность о встрече в библиотеке | PNG RGB, 720×600, около 19 КБ |
| `warning.wav` | Голосовое сообщение с просьбой о защитном переводе и коде | WAV PCM16, 16000 Гц, моно, 12.47 с, около 404 КБ |
| `ordinary.wav` | Голосовое сообщение о встрече | WAV PCM16, 16000 Гц, моно, 6.72 с, около 220 КБ |

`*-chat.txt` содержат текст картинок; `*-voice.txt` — текст аудио. Аудио синтезировано установленным голосом macOS Milena. Это пример голосового сообщения одного участника, а не проверка разделения двух людей.

## Порядок показа

1. До защиты настроить локальные веса и запустить сайт. Проверить оба режима этими файлами и сохранить фактические результаты; при ошибке исправить причину до показа.
2. Выбрать «Скриншот переписки», загрузить `warning.png`. На результате показать извлеченный текст, найденные признаки, цитаты и ограничения. В примере содержатся P, C, S, U и A; их фактическое обнаружение зависит от OCR и текстовой модели.
3. Загрузить `ordinary.png` как контраст. Проверить фактический результат заранее, не обещать комиссии отсутствие всех ложных срабатываний.
4. Выбрать «Аудиозапись», загрузить `warning.wav`. Показать распознанный текст и привязку находок к записи. Для сравнения есть `ordinary.wav`.
5. При необходимости вставить содержимое соответствующего TXT в текстовый режим и сравнить с распознаванием. Это диагностический контроль, а не подмена результата медиа.

Называть эти файлы учебными постановочными примерами. Не выдавать их за реальные обращения мошенников или независимую оценку качества.

## Свои файлы

Для первой демонстрации использовать короткую запись 10–30 секунд в тихой комнате, без музыки и наложения голосов. Для диалога два человека читают реплики по очереди с паузами. Не просить участников называть настоящие коды, счета или другие личные данные.

Ограничения загрузки: WAV PCM 16 бит, 16000 Гц, один или два канала, до 60 секунд и 4 МиБ; скриншот PNG/JPEG до 5 МиБ и 4 млн пикселей. Пример 720×600 содержит 432 тыс. пикселей. Текст должен быть крупным, пузыри с обеих сторон видны целиком, порядок сверху вниз.

Если телефон записал M4A/MP3, подготовить WAV заранее на компьютере с FFmpeg:

```bash
ffmpeg -i recording.m4a -t 30 -ar 16000 -ac 1 -c:a pcm_s16le recording-demo.wav
```

У программы обработки нет автоматического обещания надежно разобрать оформление любого мессенджера. На защите показывать ограничение, если порядок или участник определены неуверенно.

## Повторное создание примеров

Картинки создаются Pillow, шрифт не входит в репозиторий:

```bash
python examples/demo/build.py --font /path/to/font-with-cyrillic.ttf
```

На macOS можно заново создать и PNG, и WAV установленным голосом Milena без скачиваний:

```bash
python examples/demo/build.py --audio
```

Проверены размер/формат файлов, чтение WAV существующим `read_wav` и разделение сторон по известным координатам текста. Реальные ASR/OCR и срабатывания моделей на этих примерах пока не проверялись.
