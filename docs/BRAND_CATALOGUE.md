# Справочник организаций

На 5 ноября 2026 года: 63 организации, 165 доменов. Это сравнение с ожидаемой организацией, а не список безопасных страниц.

## Состав

- 38 банков: прежние Альфа-Банк, Сбербанк и ВТБ плюс Т-Банк, Газпромбанк, Совкомбанк, Россельхозбанк, Райффайзенбанк, МТС Банк, Яндекс Банк, Озон Банк и другие.
- 25 сервисов и госорганов: Госуслуги, ФНС, СФР, ФССП, Банк России, Почта России, СДЭК, Ozon, Wildberries, Авито, Яндекс, ЮKassa, ЮMoney, МТС, МегаФон, Билайн, t2, Ростелеком, РЖД, Аэрофлот, ВКонтакте, Почта Mail, Telegram, Деловые Линии и ПЭК.

Полный список — `analysis/brands.json`. У записи есть название, русские и латинские варианты, обозначения для поиска в hostname, домены, первичные источники и дата проверки. Банки проверены по интернет-ресурсам карточек Банка России; сервисы — по официальным страницам и документам. Для `wb.ru` приведен документ ФИПС, для Авито — договор платежного партнера с указанием ресурса.

Общие соцсети и мессенджеры из банковских карточек не становятся доменами банка. Например, `t.me/AlfaBank` не добавляет `t.me` к Альфа-Банку. Домены Telegram хранятся только в записи Telegram.

## Сопоставление

1. По введенному названию ищется точное совпадение с нормализованным названием или алиасом.
2. По введенному адресу выбирается наиболее конкретный совпавший домен. `bank.yandex.ru` относится к Яндекс Банку, общий `yandex.ru` — к Яндексу.
3. Без ожидаемой организации сначала проверяются известные домены, затем обозначения брендов в hostname. Длинное конкретное обозначение имеет приоритет над общим; равная неоднозначность означает неизвестность.
4. Домен сравнивается целиком по границе метки. `login.bank.ru` может совпасть с `bank.ru`, а `bank.ru.foreign.example` — нет. Название в пути, query или перед `@` не подтверждает домен.

Справочник не снижает числовую оценку фишинга и не выдает ответ «безопасно». Совпадение с VK, Telegram, маркетплейсом или другим сервисом не подтверждает пользователя, продавца или страницу. Содержимое и перенаправления по-прежнему не открываются.

## Обновление сохраненных моделей

Выбранная CNN читает текущий `analysis/brands.json` при загрузке. После изменения справочника нужен перезапуск процесса; его хеш входит в новую URL-версию. Перепаковывать веса CNN не требуется.

Прежний `URLModel.save` для CatBoost включает справочник в manifest. Изменение исходного JSON не меняет такие артефакты. Для их явного обновления:

```bash
python -m ml.update_catalogue var/ml/url-01 var/ml/url-01-brands-20261105
```

Либо передать полный каталог с `text/`, `url/` и `calibration.json` (прежние комплекты с `risk/` также поддерживаются):

```bash
python -m ml.update_catalogue var/ml/site-bundle var/ml/site-bundle-brands-20261105
```

Выходная папка должна быть новой и находиться вне исходной. Команда проверяет исходную URL-модель, копирует CBM без изменения байтов, сохраняет сведения обучения и записывает новый справочник с новой URL-версией. В полном комплекте проверяются все заявленные исходные версии и восемь порогов; изменяется только `calibration.versions.url`. Пороги и остальные веса сохраняются. Старый комплект не изменяется; при размещении нужно явно выбрать новый.

Политика `specific-domain-v2` записана в самом справочнике. Артефакты без этой отметки сохраняют старое сопоставление. Перепаковка не является переобучением и не доказывает неизменность качества всего сервиса: для новых организаций меняются пояснения о доменах. Новые ответы используют warning-rules-v1; старое дерево не вызывается.
