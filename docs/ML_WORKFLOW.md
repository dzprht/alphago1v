# Подготовка обучения

5 ноября 2026. Итоговое предупреждение формируют правила, отдельная обучаемая risk-модель сайту не нужна. Артефакты и данные кладем в `var/ml/`, вне Git. Ниже описаны текущие нативные адаптеры E5 + LR и URL CatBoost; выбранные в экспериментах rubert-tiny2 и символьная CNN еще требуют подключения.

## Что куда идет

```text
аудио → Whisper + pyannote → Turn ┐
скриншот → EasyOCR + пузыри → Turn ├→ E5 + 7 LR → 14 текстовых оценок
текст → Turn                    ┘
URL → 12 признаков → CatBoost ──────────────────┐
анкета + история → флаги перевода ──────────────┼→ явные правила → ответ
текстовые оценки → пороги и объединение анкеты ┘
```

`Analyzer.prepare` собирает входы без итогового решения. Его используют получение оценок признаков и обычный `Analyzer.analyze`. Исследовательский вектор из 105 признаков сохранен для старых экспериментов; сайт не передает его обучаемому дереву. Пропущенное значение остается неизвестным через маску; экспертные метки в признаки не попадают.

## Входные файлы

**Текстовый train:** существующий формат `ml.train_text`: `case_id`, `group_id`, `split=train`, `target_turn_id`, `fragment_id`, `turns`, `labels` и `evidence`. Последние два поля — списки из семи меток `0/1/null` и цитат в порядке `TEXT_LABELS`; положительной метке нужна цитата из выбранного фрагмента. Обязателен отдельный `group_id` для связанных диалогов, переводов и перефразирований.

**URL train:** формат `ml.train_url`: `url` — полный адрес, `label` — бинарная метка, `group` — зарегистрированный домен, `split=train`. Подготовка PhiUSIIL остается в `ml.prepare_urls`.

**Сценарии:** JSONL, одна строка на целевую реплику. Общие исходники одного `case_id` должны совпадать. Один случай с несколькими целями записывается несколько раз.

| Поле | Значение |
| --- | --- |
| `case_id`, `group_id` | Идентификаторы случая и исходной группы |
| `split` | `train`, `validation`, `calibration`, `test`; файл содержит все четыре части |
| `kind` | `text`, `url`, `transfer`, `audio`, `screenshot` |
| `input_data` | Поля после проверки формы; сумма в целых копейках, без исходного CSV |
| `checked_at` | ISO-время проверки с часовым поясом |
| `target_turn_id` | ID целевой реплики; `input` для обычного текста/просьбы; `null`, если текста нет |
| `risk` | Необязательная старая экспертная метка `0/1/2/null`, только для исследования risk-моделей |
| `turns` | Необязательные сериализованные `Turn`: ID, текст, говорящий, владелец, источник |
| `order_known` | Известен ли порядок; по умолчанию `true` |
| `history` | Необязательные нормализованные операции: копейки, направление, время, получатель |
| `extraction` | Для медиа обязателен настоящий выход ASR/OCR: статус, реплики, порядок, версия, ограничения |
| `labels` | Для calibration/test — восемь меток признаков `0/1/null` |

Восемь ключей `labels`: `text_urgency`, `text_money_request`, `text_credentials_request`, `text_secrecy`, `text_remote_access`, `text_authority_claim`, `text_protective_transfer`, `url_score`. Это содержание целевой реплики и предшествующих реплик того же известного участника; `url_score` — наличие фишинга хотя бы у одной доступной для этой цели ссылки. Неизвестное или неприменимое — `null`. Смысл текстовых признаков — в `ML_PLAN.md` и `analysis.text.TEXT_LABELS`; имена в файле должны точно совпадать с `analysis.runtime.THRESHOLD_NAMES`.

Для исторического сценария передаем только операции, доступные до `checked_at`. Текущая проверка сайта использует всю загруженную историю; будущие относительно проверки даты ограничивают ее достоверность. Подготовщик не вырезает такие строки молча.

Для `score_cases` и `calibrate` поле `risk` не требуется. В исследовании старых risk-моделей оно размечается отдельно, а не суммой признаков. Отзывы пользователей не становятся эталоном автоматически. Выгрузки из БД здесь нет; полный CSV и исходные пользовательские медиа в обучение не передаем.

## Порядок запуска

Нужны готовые `final/text` и `final/url`, окружение с группой `ml` и локальным E5. В `manifest.training` обеих моделей должны быть `selected_group_ids`, `selected_case_ids`, `selected_domains`: списки групп, случаев и доменов, использованных при обучении и выборе модели. Пустой список допустим только при фактическом отсутствии таких исходников. Без этих сведений `calibrate` не может проверить независимость и отклоняет комплект.

```bash
python -m ml.score_cases var/ml/scenarios.jsonl var/ml/experiment/final var/ml/experiment/calibration-scores.jsonl
python -m ml.calibrate var/ml/experiment/calibration-scores.jsonl var/ml/experiment/final
```

1. **Разделить исходники.** Связанные диалоги, перефразирования, переводы и медиа держать в одной группе. Calibration и test не участвуют в обучении или выборе модели; URL-домены этих частей не должны попадать в обучение.
2. **Получить оценки calibration.** `score_cases` загружает только text/url, без дерева и без обучения. Формирует семь максимумов текстовых оценок и `url_score`, сохраняет неизвестность и источники разбиения. Положительные ответы анкеты не подменяют модельные оценки при подборе порогов.
3. **Подобрать пороги.** Для каждого из восьми признаков выбирается максимум F1; при точном равенстве — больший порог. Нужны оба известных класса. `calibrate` сравнивает группы, случаи и домены calibration с `selected_*` обеих моделей. Выход `final/calibration.json` связан только с версиями text/url и подходит текущему HTTP-загрузчику.
4. **Собрать ответ правилами.** Пороговые флаги и положительные ответы анкеты объединяются максимумом. Баннер: `C или P или R или F или [M и (U или S или A)] или [D и (H или N)]`. Текстовые сочетания относятся к одному автору; H/N/D — к проверяемому переводу. Неизвестность не является положительным флагом.

Обозначения флагов и таблица предупреждений зафиксированы в [SPECIFICATION.md](../SPECIFICATION.md).

При изменении нижних моделей заново получаем независимые оценки и подбираем пороги. Версии комплекта и calibration должны совпадать. Для баннера не нужны OOF-признаки, risk-метки или risk-артефакт.

После фиксации параметров `score_cases --split test` получает оценки признаков независимого теста. Он не считает полный отчет качества продукта: срабатывания правил по целым диалогам, медиаметрики, задержки и память остаются отдельной работой. Не используем test для подбора порогов.

## Старые risk-эксперименты

`ml.prepare_risk` и `ml.train_risk` сохранены для исследования и сравнения. Подготовщик также умеет получить нативные итоговые text/url-модели с `selected_*`; при этом он дополнительно считает OOF, которые сайту не нужны:

```bash
python -m ml.prepare_risk var/ml/scenarios.jsonl var/ml/text-train.jsonl var/ml/url-train.jsonl var/ml/experiment
```

Необязательное обучение старого дерева выполняется отдельно:

```bash
python -m ml.train_risk var/ml/experiment/train.jsonl var/ml/experiment/final/risk --validation var/ml/experiment/validation.jsonl
```

Для него нужны отдельные `risk=0/1/2` и групповые OOF-прогнозы моделей, не обучавшихся на целевой группе. Эти метки и веса не используются для предупреждений на сайте.

## Медиа

- `AudioRecognizer.from_local`: локальные faster-whisper-small и pyannote community-1. Веса Whisper должны включать `model.bin`, `config.json`, `tokenizer.json`; конфигурация pyannote должна ссылаться на локальные веса. Скачивания и телеметрия в загрузчике выключены. Доступ к community-1 требует принятия условий модели заранее.
- Текущий декодер принимает только WAV PCM16, 16 кГц, один или два канала. Обычное стерео смешивается в моно. Раздельные каналы A/B допустимы только при известной изоляции голосов; по умолчанию этот режим выключен.
- Whisper дает слова и время, pyannote — интервалы голосов. Слово получает участника только при полном однозначном покрытии. Наложения не считаются разделенными. Метка A/B не определяет владельца.
- `ScreenshotModel.from_local`: локальные EasyOCR CRAFT и `cyrillic_g2`, RU/EN, без скачиваний. OCR-строки объединяются внутри найденных цветовых пузырей. При различимых обеих сторонах назначаются A/B; иначе участник неизвестен.
- Геометрия пузырей — прототип. Надежная поддержка оформления любых мессенджеров не подтверждена. Частичное распознавание, неизвестный порядок и ошибки передаются общему анализатору явно.
- Пороги качества и лимиты передаются явно. Их предстоит подобрать на размеченных медиа; сырой confidence не является измеренной точностью. Тесты используют подставные ASR/OCR-выходы и нарисованные изображения, реальные веса еще не запускались.
- HTTP-загрузки медиа выключены. До включения нужны измеренные лимиты, временные файлы с удалением при ошибках и связь загрузки с распознавателем.

## Окружение

В lock-файл добавлена отдельная группа `media`. PyTorch закреплен на 2.11.0 вместе с torchaudio 2.11.0, torchvision 0.26.0 и torchcodec 0.17.0: совместимая пара для pyannote и EasyOCR. На Linux используются CPU-колеса. Нужен системный FFmpeg для аудиостека. Общий рабочий venv не изменялся.

Будущую установку тяжелых библиотек сначала проверяем в отдельном окружении через `uv sync --group ml --group media`. Обычный CI ставит только базовые зависимости и проверяет логику на подставных моделях; он не подтверждает работу нативного медиастека.
