# План реализации

Актуален на 25 октября 2026 года. Django + Django Templates + PostgreSQL, разработка с нуля.
Объём: [F01–F09](SPECIFICATION.md). Общий продукт: [заявка](kharchenko_application.md).

По последнему решению пользователя порядок такой: **бэкенд → фронтенд → ML**. Ранние ML-эксперименты откладываем. Каждую часть записываем, объясняем и останавливаемся до её просмотра и одобрения; один пункт ниже может состоять из нескольких таких порций. Сроки — ориентир, а не разрешение продолжать без просмотра.

## Зависимости и ограничения

- Модель пользователя определяем до первого применения миграций.
- Серверную логику сначала проверяем тестами; страницы и реальный анализ подключаем отдельными этапами.
- Импорт CSV нужен для персонального анализа перевода, но проверка перевода должна работать и без него.
- Аудио и скриншоты используют общий текстовый анализатор.
- При поздней проверке ML меньше времени на исправление проблем с данными и ресурсами. Это риск выбранной последовательности, а не повод автоматически менять объём.
- Подготовку опроса и интервью, тесты и документацию можно вести по ходу работы; разработку следующей порции начинаем только после просмотра текущей.

Новые функции и сокращение F01–F09 обсуждаем отдельно. Документы и заглушки не считаем готовыми функциями.

## Остаток на 3 ноября

После сборщика ответа написано около 2.6 тыс. строк Python и HTML, без тестов и миграций; тестов отдельно около 2.6 тыс. Строки считаются с комментариями и пустыми строками. Это объем кода, не процент готовности продукта.

| Что осталось | Дополнительные строки кода без тестов |
| --- | ---: |
| ASR, участники аудио, OCR, пузыри и порядок переписки | 400–750 |
| Подготовка корпусов, OOF, обучение, калибровка и оценка | 350–650 |
| Общий запуск, HTTP, сохранение, оформление и адаптивность | 500–900 |
| Размещение и оставшиеся небольшие исправления | 100–200 |
| Всего | 1350–2500 |

Тесты дополнительно: примерно 400–800 строк. Итог собственного кода — ориентировочно 4–5.2 тыс. строк, тесты отдельно. Диапазон предполагает простую реализацию с явным отказом при непригодном распознавании, а не надежное разделение всех возможных интерфейсов мессенджеров.

Главный остаток работы — данные и проверка: у текста пока 14 демонстрационных примеров, у дерева нет рабочего risk-корпуса и полученных на нем OOF-признаков, медиавеса не проверены. Код адаптеров и обучающих команд добавлен 4 ноября; прежняя таблица выше остается оценкой на 3 ноября. Нужны разметка, независимая оценка, проверка реальных аудио и скриншотов, время и память на сервере. Также остаются восстановление аккаунта, выбор хостинга и сроки хранения, проверка размещения и материалы защиты. Эти задачи не измеряются числом написанных строк.
