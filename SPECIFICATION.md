## Объём

| ID | Функция | Условие готовности |
| --- | --- | --- |
| F01 | Аккаунт | Пользователь регистрируется, входит и выходит; после входа с другого устройства доступны его данные. Чужие данные недоступны. |
| F02 | Проверка текста | Сообщение или диалог получает объяснённый результат; пустой ввод отклоняется. |
| F03 | Проверка ссылки | URL получает результат; некорректный адрес отклоняется. Сервер не открывает переданный сайт. |
| F04 | Проверка аудио | Из записи извлекается текст и анализируется содержание; неразборчивая запись не получает ответ «безопасно». |
| F05 | Проверка скриншота | Из изображения извлекается текст с сохранением порядка реплик и анализируется содержание; ошибка распознавания явно обозначается. |
| F06 | Проверка перевода | Оцениваются сумма, назначение и доступный контекст. Загруженная история используется; без неё проверка остаётся доступной с соответствующим ограничением. |
| F07 | Импорт истории | Вошедший пользователь загружает CSV по шаблону либо вводит операции строками. Данные проверяются до замены истории; неудачный импорт не меняет старые данные. |
| F08 | История проверок | Вошедший пользователь открывает свой список и сохранённый результат. Просмотр не запускает повторный анализ и не изменяет исходный прогноз. |
| F09 | Обратная связь | Вошедший пользователь может добавить и исправить исход своей сохранённой проверки с готовым результатом. Отзыв хранится отдельно от прогноза и не запускает обучение. |

Аккаунт — одно требование. Объяснения и обработка ошибок входят в проверки. Просмотр и удаление импортированной истории, экспорт результата, учебные карточки и демокаталог не добавлены как отдельные обязательные функции.

## Аккаунты и HTTP

Регистрация требует логин, пароль и повтор пароля. После создания аккаунта пользователь переходит на вход без автоматической авторизации. После входа доступна страница `/accounts/` с логином и POST-формой выхода. Выход завершает только текущую сессию. POST регистрации, входа и выхода требуют CSRF-токен; GET выхода возвращает 405. Переданный клиентом `next` пока не используется.

Пять неверных попыток входа с одного IP за 15 минут от первой ошибки блокируют следующие попытки до конца окна. Заблокированный запрос не проверяет пароль и не продлевает окно: возвращает 429 и `Retry-After`. Успешный вход не сбрасывает накопленные ошибки IP; счетчик обнуляется только после окончания окна. Лимит хранится в PostgreSQL и применяется HTTP-обработчиком по `REMOTE_ADDR`, без доверия к клиентскому `X-Forwarded-For`. Общий IP означает общий лимит; за прокси требуется настройка достоверного IP до публичного запуска.

Сессия живет по настройкам Django: 14 дней с последнего сохранения, без продления обычным чтением страниц. Отдельного таймера неактивности нет. Восстановление пароля еще не выбрано; F01 не объявляем завершенной до этого решения и подключения личных данных к страницам.

## Гостевой режим

Все пять проверок F02–F06 доступны без входа. Для гостевого перевода используются только введённые сведения, без персональной истории операций. Постоянная история, CSV и обратная связь к сохранённым проверкам доступны только в аккаунте.

Гостевой ввод и результат существуют только для текущей проверки: не записываются в БД, cookie или серверную сессию. После закрытия или перезагрузки страницы результат может потеряться; интерфейс предупреждает об этом. Временная обработка медиа и их удаление действуют в обоих режимах.

Гостевой режим не даёт доступа к сохранённым проверкам других людей. Вход и последующая проверка создают обычную запись владельца; гостевые результаты автоматически в историю не переносятся.

## Аккаунт

Регистрация принимает логин, пароль и повтор пароля. Email, телефон и имя не требуются. Форма отклоняет занятый логин, в том числе отличающийся только регистром, несовпадающие и слабые пароли. Уникальность без учета регистра также закреплена в БД через UPPER(username); конфликт одновременного сохранения возвращается ошибкой поля логина. Новый пользователь не получает административных прав. Создание аккаунта само по себе не выполняет вход. Восстановление пароля решаем отдельно до завершения F01.

Вход принимает логин в выбранном при регистрации написании и пароль. При успехе используется серверная сессия Django в PostgreSQL. Неверные учетные данные и неактивный аккаунт не дают войти. Выход завершает текущую сессию; аккаунт и другие сессии сохраняются.

## Входные данные

На `/` показаны пять режимов; `/checks/new/<kind>/` доступен гостю и аккаунту. Один обработчик использует существующие формы. Неверные поля и файлы дают 400 до загрузки моделей. При отсутствии или несовместимости комплекта верный ввод дает 503 без создания проверки. При готовом Analyzer аккаунт получает сохраненную проверку и redirect, гость — временный ответ без записи или сессии. Для медиа локальные распознаватели загружаются лениво через load_media_model и переиспользуются на процесс; сетевых скачиваний из HTTP нет.

План входов уточнён 1 ноября: у текста, ссылки, аудио и скриншота остаются необязательные **«Дополнительные обстоятельства»**, отдельно от исходных реплик. 2 ноября у перевода свободный пересказ заменён анкетой; исходная просьба осталась отдельным полем. 5 ноября поля ручного описания участников аудио и скриншота удалены; разделение выполняется автоматически.

| Проверка | Обязательно | Необязательно | Зачем нужны дополнительные сведения |
| --- | --- | --- | --- |
| Текст | Текст сообщения или диалога | Дополнительные обстоятельства | Восстановить контекст, которого нет в самом сообщении. |
| Ссылка | URL | Сопроводительное сообщение; ожидаемый сайт или организация; дополнительные обстоятельства | Понять цель перехода и заявленный пользователю источник. Название организации не подтверждает подлинность сайта. |
| Аудио | Аудиофайл | Дополнительные обстоятельства | Учесть события вне записи; участников разделяет обработчик автоматически. |
| Скриншот | Одно изображение | Дополнительные обстоятельства | Учесть часть переписки вне кадра; сообщения и стороны разделяются автоматически. |
| Перевод | Сумма в рублях; назначение из списка | Получатель из истории или стабильный ID; оригинальный текст просьбы; анкета обстоятельств | Сопоставить получателя с историей и проверить обстоятельства и исходное обращение. |

В проверке URL поле ожидаемой организации предлагает названия из справочника: на 5 ноября 63 организации и 165 доменов. Свободный ввод остается доступен; неизвестная организация не получает выдуманного совпадения. Для вложенных сервисов выбирается наиболее конкретный домен. Совпадение с доменом платформы не подтверждает отправителя, продавца или содержимое страницы. Источники и порядок обновления — [BRAND_CATALOGUE.md](docs/BRAND_CATALOGUE.md).

Назначение перевода: **покупка / возврат долга / подарок или помощь / между своими счетами / другое / неизвестно**. Это обязательный выбор, но вариант «неизвестно» позволяет продолжить без выдуманного ответа.

Анкета перевода: кто попросил, канал обращения, торопят ли, требуют ли секретности, менялись ли реквизиты. Неизвестный ответ допустим и выбран по умолчанию; отсутствие ответа не равно «нет». Конкретные значения и обработка перечислены в [ML_PLAN.md](ML_PLAN.md). Анкета не превращается в текст; необязательную оригинальную просьбу анализирует общий текстовый блок.

5 ноября объединены совпадающие признаки анкеты и модели: срочность, секретность и представление сотрудником организации. Положительный ответ дает объединенную оценку 1; иначе остается максимум текущей и предыдущих оценок модели того же участника. «Нет» и «неизвестно» не подавляют модель. В результате сохраняются исходная оценка, объединенная оценка и основания «Указано вами» / «Обнаружено в сообщении»; оба основания показываются в одной карточке. Канал и смена реквизитов не подменяют текстовые признаки. Вход и прогноз старого дерева сохранены; при найденных признаках его нулевой прогноз не сопровождается заголовком об отсутствии признаков. Политика выдачи — result-v2.

Аудио и личные переписки любых мессенджеров обрабатываются без ручного подтверждения реплик и участников. Различение A/B не устанавливает, кто пользователь. При неизвестном оформлении, владельце или порядке реплик эти сведения остаются неизвестными; ограничения показываются в результате.

Сумма положительная, с точностью до копейки. На вводе не более 16 цифр до разделителя и двух после: целое число копеек будет меньше 10^18 и поместится в 64-битное поле. В подготовленных данных используется `amount_kopecks`, без `float`. Валюта первой версии — только RUB. Номера карт и счетов для идентификации получателя не требуются: достаточно согласованного с CSV обозначения. Похожие имена сами по себе не подтверждают, что это один человек.

Для ссылки требуется полный адрес с `http://` или `https://`; протокол автоматически не подставляется, сайт не открывается. Серверные формы проверяют обязательные поля, допустимое назначение и сумму. Аудио: WAV PCM16, 16000 Гц, один или два канала, до 60 секунд и 4 МиБ; проверяются заголовок и целостность данных. Скриншот: статический PNG/JPEG, до 5 МиБ и 4 млн пикселей; проверяются формат и содержимое. Точное описание — [MEDIA.md](docs/MEDIA.md).

История берётся из аккаунта, её не нужно загружать при каждой проверке. Для гостя она не используется. Без сопоставленного получателя не делаем вывод о его новизне. Без достаточной истории не оцениваем сумму как необычную относительно прошлых операций.

Признаки исходного текста извлекает анализатор. В переводе ответы анкеты хранятся отдельно от признаков оригинальной просьбы и не перезаписывают их. Пропуски означают отсутствие информации, а не отсутствие риска.

Русский язык — основной язык первой версии. Проверка аудио касается содержания готовой записи; подключение к звонку в реальном времени и определение мошенника по голосу не входят в объём. Скриншот проверяется по содержанию, а не на подлинность изображения.

## Результат проверки

На странице результата показываем:

- обнаруженные признаки и их объяснения с привязкой к доступному материалу;
- рекомендации, что пользователю стоит проверить самостоятельно;
- ограничения: неполный контекст, отсутствие истории, качество распознавания;
- дату проверки и версию анализатора; для медиа — извлечённый текст.

С 5 ноября новые ответы используют правила из [WARNING_POLICY.md](docs/WARNING_POLICY.md): C/P/R/F, M вместе с U/S/A, смена реквизитов вместе с нетипичной суммой или отсутствующим в истории получателем. Обозначения: C — секреты, P — защитный перевод, R — ПО или доступ, F — URL выше порога, M — денежная просьба, U — срочность, S — секретность, A — роль сотрудника, D — смена реквизитов, H — нетипичная сумма, N — получатель отсутствует в истории. Баннер, отдельные замечания, достаточность и технический статус хранятся раздельно. У новых ответов risk=null; дерево и классы 0/1/2 не применяются. Частичное распознавание сохраняет найденные основания с ограничением. Пустой ввод и сбой не становятся отрицательным ответом. Проценты мошенничества не показываем. Поля назначения и канала сохраняют контекст, но не дают баллы. Сумма: Modified Z>3.5, минимум 20 исходящих; MAD=0 означает неизвестность. Положительный ответ анкеты не подавляется моделью, внешний инициатор перевода дает M. Старые сохраненные результаты не пересчитываются.

`finish_check` завершает только ожидающую проверку: готовый непустой JSON-результат с версией анализатора дает статус `completed`; понятное сообщение об ошибке дает `failed`, а `result` остается `None`. Сообщение хранится отдельно в `error_message`. Оба исхода терминальные: новая попытка создает новую проверку. Повторное завершение через эту операцию не переписывает сохраненный итог, в том числе при устаревшей копии записи.

В аккаунте исходный результат сохраняется как снимок. Последующий отзыв, замена CSV или новая версия модели его не переписывают. Гостевой результат остаётся временным и в личную историю не попадает. Проверка признаков риска не гарантирует обнаружение мошенничества или безопасность операции.

Снимок отделен от словарей, переданных обработчиком: последующее изменение этих словарей не меняет итог. Для гостя завершение меняет только объект в памяти; личный контекст истории ему передавать нельзя. Категории риска и состав содержимого `result` эта операция пока не определяет.

История доступна после входа на `/checks/`, свой сохраненный результат — на `/checks/<id>/`. GET ничего не меняет и не запускает анализ; чужой или отсутствующий ID дает 404. Новые результаты показывают оценку, достаточность, признаки с источниками, советы и ограничения; у старых записей остается экранированный JSON fallback.

## CSV и история операций

5 ноября добавлен второй обязательный способ: ручной ввод до 100 операций на странице истории. У строки есть дата и время по Москве, сумма в рублях, направление и необязательное обозначение контрагента. Строки можно добавлять и отмечать на удаление. Добавление работает и без JavaScript через серверную кнопку. Оба способа используют общие проверки операции и одну атомарную замену личной истории; ввод одной строки не дописывает ее к прежней истории.

Поддерживаем собственный [шаблон CSV](examples/transactions.csv), а не произвольные выписки всех банков. Полный формат: [docs/CSV_FORMAT.md](docs/CSV_FORMAT.md). Кодировка UTF-8 с необязательным BOM, разделитель `;`, колонки строго в порядке `occurred_at;amount;direction;recipient`. Лимит — 2 МиБ и 10 000 операций; нужна хотя бы одна операция.

Дата и время обязательны, ISO 8601 с явным часовым поясом; внутри приводятся к UTC. Сумма положительная в рублях, до 16 цифр до разделителя и двух после, сохраняется целым числом копеек. Направление обязательно: `incoming` — поступление, `outgoing` — списание. Колонка `recipient` обязательна, но значение можно оставить пустым: это условный ID контрагента до 100 символов, для списания — получатель, для поступления — отправитель. После удаления внешних пробелов ID сопоставляется точно, с учетом регистра; похожие имена не объединяются.

Новый корректный импорт полностью заменяет активную историю пользователя одной транзакцией БД. При ошибке старая история сохраняется целиком. Повторная загрузка не удваивает операции; совпадающие строки внутри файла сохраняются. Импорт и удаление одного пользователя выполняются последовательно с блокировкой строки владельца. Исходный файл не сохраняется приложением; в БД остаются операции и сведения об активной загрузке, включая период. SHA-256 сохраняется для CSV; при ручном вводе поле пустое, поскольку файла нет.

Подготовлены чтение и удаление своей истории. По решению от 1 ноября все проверки относятся к текущему моменту: дату перевода пользователь не вводит, история по времени проверки не отсекается. Для исходящего перевода сравниваются все исходящие операции корректной истории. Непригодные даты ограничивают достоверность исторического контекста, строки молча не удаляются. Параметр `before` остаётся пригодным для исторических экспериментов; связь чтения с анализом ещё не реализована. Начальные признаки и минимум истории заданы в [ML_PLAN.md](ML_PLAN.md), их пригодность проверяется экспериментально.

На `/transactions/` после входа доступны таблица своих операций и POST-форма импорта. Скачать пример можно по `/transactions/template/`; удалить историю — только POST на `/transactions/delete/`. Перед кнопками есть предупреждения о полной замене и удалении. Форма проверяет наличие файла и размер, сервис — все содержимое. Ошибка CSV показана у поля файла, старая история остается на странице. Изменения требуют CSRF-токен; после успеха идет перенаправление на GET.

История транзакций и история проверок — разные данные. В снимке результата сохраняем использованные агрегаты и ограничения, чтобы прежний вывод оставался объяснимым после замены CSV.

## Обратная связь

Пользователь выбирает исход: **мошенничество / обычная ситуация / неизвестно**. Комментарий необязателен; в нём можно объяснить, откуда стал известен исход. Один текущий отзыв на проверку можно исправить. Сохраняем связь с проверкой, ответ, комментарий и время изменения.

Уточнение от 28 октября: отзыв и согласие доступны для своей проверки в статусе `completed`. У `pending` ответа еще нет, у `failed` есть техническая ошибка без прогноза. Форма с неверным исходом не меняет прежний отзыв.

Это непроверенное сообщение пользователя. Отсутствие потери денег не доказывает отсутствие мошенничества; отсутствие отзыва не означает успех модели. Сохраняем оба определённых исхода и неопределённые ответы. По этой выборке нельзя без дополнительной проверки объявлять объективную точность продукта.

Отдельное добровольное разрешение на использование данных конкретной проверки для подготовки будущего обучения по умолчанию выключено. Отказ не мешает проверке и отправке отзыва. До ручной проверки и отдельного решения об обучении такие записи остаются обратной связью, а не готовым обучающим набором. Дообучение, автоматическая адаптация и гарантированное улучшение качества в первую версию не входят.

Согласие хранится отдельно в `TrainingConsent`: текущее `granted`, время изменения и версия условий. Отсутствие записи означает запрет. Отзыв и согласие меняются независимо; согласие можно выдать без отзыва и затем отозвать. Разрешение действует только для выбранной проверки и текущей версии условий. Отсутствующая или устаревшая версия в форме отклоняется без изменения записи.

Текст и объем условий версии `2026-10-28`: [docs/TRAINING_CONSENT.md](docs/TRAINING_CONSENT.md). Они охватывают данные этой проверки и ее отзыв, но не остальные проверки, полную историю CSV или исходные медиа. Перед будущим обучением согласие нужно проверить снова; сейчас нет обучения, экспорта выборки или передачи данных стороннему сервису. Текст условий доступен пользователю до отправки отдельной формы согласия.

На странице готового результата подключены две отдельные POST-формы: `action=feedback` и `action=consent`. Каждая меняет только свою запись. Флажок заполняется действующим согласием; условия показаны перед формой. Ошибочный ввод сохраняет прежние данные, чужой ID дает 404. При старой версии условий показана ошибка и ссылка для обновления страницы, без молчаливой подстановки новой версии.

## Данные и доступ

Сохранённые проверки, транзакции и отзывы привязаны к владельцу. Для каждой операции с ними сервер проверяет доступ, включая обращение по прямой ссылке на результат. Извлечённый текст сохраняется для истории только в аккаунте; у гостя он временный. Исходные аудио и изображения обрабатываются временно и удаляются после завершения обработки или ошибки в обоих режимах. Содержимое проверок не записываем в технические журналы и не публикуем в GitHub.

## Изменение объёма

Новые функции сначала обсуждаем и отражаем в заявке, требованиях, сценариях и плане. Алгоритмы и библиотеки можно менять по результатам экспериментов, сохраняя согласованное поведение. Если обязательную функцию выполнить не получается, фиксируем проблему и согласуем изменение, а не молча убираем её из проекта.

## HTTP-медиа — 5 ноября

Временные файлы создаются только для обработки, через TemporaryDirectory; удаляются после результата и исключения. В БД попадают метаданные загрузки, фактический извлеченный текст и результат, а не исходный файл. Гость не получает запись в БД. При partial показываются найденные основания и ограничение; техническая ошибка не выдается за отсутствие риска. Демо-файлы и инструкции: [DEMO.md](docs/DEMO.md). Прохождение формата не доказывает качество моделей.
